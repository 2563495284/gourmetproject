# GourmetProject 配置表说明

> 面向 **策划 / 美术 / 程序** 的统一配置词典。
> 目标：任何人拿到这份文档，不用翻代码也能看懂「每张表是干什么的、每个
字段填什么、值会流向哪里」。

- **配置源**：`GameConfig/Datas/*.xlsx`（schema 与数据都在 Excel 里，**不写 JSON 源数据**）。
- **生成产物（勿手改）**：代码 → `Assets/GameMain/Scripts/Config/Gen/`；运行时数据 → `Assets/StreamingAssets/Config/*.json`。
- **生成命令**：`bash GameConfig/gen.sh`（需要 .NET SDK 8.0+）。
- **运行时访问**：统一走 `GameApp.Config.Tables.TbXxx.Get(id)`。
- **记录数**：本文中各表的「记录数」为 2026-06-25 生成时的数据行数，仅供参考，会随表更新变化。

## 1. 给三个工种的快速指引

| 角色 | 你主要关心 | 怎么读这份文档 |
| --- | --- | --- |
| **策划** | 数值、概率、解锁、节奏 | 直接看每张表的字段表与「填写提示」，重点是 `weight / 曲线 / 区间 / preconditions`。 |
| **美术** | 资源路径字段 | 搜索 `icon / portrait / 图标 / 立绘`，这些字段填资源路径，命名规范见各表备注。 |
| **程序** | 数据流向、消费方 | 看每张表的「出处与引用」，里面列出读取该表的运行时服务。 |

改字段记住三件事：① 在数据 xlsx 改表头（`##var`/`##type`/`##comment`）；② 在 `__tables__.xlsx` 登记（仅新增表时）；③ 跑 `gen.sh`。详见 [`.cursor/rules/luban-config.mdc`](../.cursor/rules/luban-config.mdc)。

## 2. 配置体系总览

```
GameConfig/Datas/*.xlsx ──(luban.conf)──> bash GameConfig/gen.sh ──┬─> Config/Gen/*.cs   (Tables 访问层)
                                                                   └─> StreamingAssets/Config/*.json (运行时数据)
                                                                            │
                                                          ProcedurePreload 整局加载一次
                                                                            │
                                                          GameApp.Config.Tables.TbXxx
```

挂载关系来自 [`GameConfig/luban.conf`](../GameConfig/luban.conf)：

| schema 文件 | 类型 | 作用 |
| --- | --- | --- |
| `Defines/builtin.xml` | — | 框架自带（vec2/vec3 等），玩法不碰 |
| `Datas/__enums_*.xlsx` | enum | 枚举定义（按主题拆多个文件，如 tag/item/reward/action/unlock/dish） |
| `Datas/__beans__.xlsx` | bean | 复合单元格子结构（`RecipeEntry` 等） |
| `Datas/__tables__.xlsx` | table | **表登记**：一行=一张表 |

## 3. 阅读约定

### 3.1 数据表表头三行

每个数据 sheet 的首列单元格用 `##` 标记行类型，字段结构「直接读表头」：

| 标记行 | 含义 |
| --- | --- |
| `##var` | 字段名（程序里的属性名） |
| `##type` | 字段类型（**结构来源**） |
| `##comment` / `##` | 字段注释（会进生成代码的文档） |

### 3.2 类型写法

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `string` `int` `float` `bool` | 基础类型 | `42` / `3.5` / `true` |
| 枚举名 | 见 [第 6 节枚举字典](#6-枚举字典)，填**枚举名字符串** | `Passive` `Boss` |
| `list,string` | 字符串数组（多行模式，字段名前加 `*`） | 形状/材质列表 |
| `list,Bean` | 复合元素数组，每元素一个单元格，靠 bean 的 `sep` 切分 | `rice,150,0,5` |
| `Bean` | 单个复合值，一个单元格按 `sep` 切分 | `min,max` |

### 3.3 多元素 list（多行模式）

字段名前加 `*`。每个元素占一行，**续行所有前导列留空**，靠主键列是否为空区分记录。多个列表需要逐行对齐时可并列放在表尾，例如 `table_fragment` 的 `*shapeRows` / `*materialIds`。

### 3.4 空值约定

- 字符串「空串」通常表示「无 / 任意 / 不限」，各表会在说明里点明（如 `weekFilter` 空=任意周、`characterPool` 空=任意角色）。
- 数值字段约定多见 `<=0 表示不限/使用默认`，以字段说明为准。

### 5.1 菜品 / 技能 / 风味 / 格子标签

#### TbDishBase — 菜品本体

菜品不随技能/风味变化的物理属性。形状用 `*shapeRows` 多行字符串描述，`'X'` 表示占用格。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 菜品基础ID（主键），供 `TbDishVariant.baseId`、菜谱池和运行时 `DishDef.BaseId` 引用；建议用英文蛇形命名，如 `cookie`、`double_cake` |
| name | string | 菜品显示名称，用于 UI、技能来源和甜蜜传递来源标签 |
| deliciousness | int | 基础美味度（基础分）；进入单菜结算的初始加法分，永久分数加成会叠在此基础上 |
| icon | string | 图标资源路径（美术），约定指向 `Sprites/Dishes/<id>`，不含文件扩展名 |
| allowRotate | bool | 是否允许玩家旋转摆放；`false` 表示只按 `TbDishVariant.rotation` 的固定朝向入场 |
| skills | list,string | 菜品技能ID列表，`\|` 分隔 → `TbSkill.id`。**一菜一 skill**：实际每道菜只填一个 `sk_<菜id>`，该菜所有效果都是它的子技能 |
| category | string | 菜品分类（如 `cake`；空=无）。被 `CategoryCount` 前提、`SkillScope.Category`、`actionParam=cat:xxx` 和 `TbCakeLayerBuff.category` 使用 |
| countAs | int | 「视为食物数」本体基础值，**恒为 1**；「视为N个食物」改由该技能自己的被动子技能（`sk_<菜id>_<序号>`）承载，运行时按 `base 1 + 增量` 叠加 |
| `*shapeRows` | list,string | 菜品形状，每行一字符串，`X`=占用格、空白=不占格；多行模式续行前导列留空，宽高会影响摆放、`ShapeMatch` 和 `OccupiedCell` 前提 |

> **填写提示**：sprite 尺寸按格子原生尺寸生成（1x1=512²、2x1=1024×512、2x2=1024²），纯食品不拟人化，见 [`food-asset-style.mdc`](../.cursor/rules/food-asset-style.mdc)。

#### TbDishVariant — 菜品变体（随机库条目）

引用本体 + 风味 + 隐藏分/权重/价格。菜品固有技能配置在 `TbDishBase.skills`；`flavorId` 空串=无风味（风味槽为空）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 变体ID（主键），奖励、商店、菜谱池通常引用此 ID；无风味普通变体一般与 `baseId` 同名 |
| baseId | string | 引用的菜品本体ID → `TbDishBase.id` |
| flavorId | string | 风味ID（可空，单槽）→ `TbFlavor.id`；空串表示无风味，生成的 `DishDef` 不带风味标签 |
| baseWeight | float | 随机基础权重；同一奖励池内按权重加权抽取，0 表示基本不应自然抽到 |
| price | int | 商店基础价格；上架时按 `GameBase.shopPriceFluctuationPct` 随机浮动，之后商店折扣/涨价类道具再修正 |
| hiddenRange | [HiddenRange](#hiddenrange) | 出现隐藏分区间，单元格写 `min,max`；用于按当前隐藏分过滤可出现的菜品变体 |
| rotation | [DishRotation](#dishrotation) | 固定旋转朝向（整格四向）：`Deg0` 不旋转、`Deg90` 顺时针90度、`Deg180` 180度、`Deg270` 顺时针270度；`allowRotate=false` 时自动上菜只用该朝向 |

#### 技能两层模型（TbSkill → TbSubSkill）

技能拆成两层，把**技能编排**与**具体效果**分离。`sub_skill` 只表达 `skill` 的明细行和关联关系，不作为可复用的公共效果库：

- **TbSubSkill（具体子技能）**：一行 = 某个技能的一条完整效果，含全部 `SkillRuleDef` 字段（trigger/condType/condScope/condUnit/condMode/condCompare/condThreshold/condParam/actionType/actionScope/actionCount/actionValue/actionParam）+ `isPassive/signed/descTemplate`。ID 固定为 `<skillId>_<从 1 开始的序号>`；即使效果内容相同或此前使用同一行，也必须为每次关联单独配置一行。
- **TbSkill（技能元信息）**：`id/termId/subSkills`；`subSkills` 正向、有序引用子技能 id（`|` 分隔），执行顺序即列表下标。描述由所引用子技能的占位符模板**按序自动拼接**。技能展示标题按 `termId` 术语名（无则空）。

运行时适配层（`GameplayContentBuilder`）遍历 `subSkills`，把每个具体子技能合成为现有的 `SkillRuleDef`（`order`=下标）。**一菜一 skill**：`TbDishBase.skills` 每菜只引用一个技能，甜蜜传递作为其子技能；运行时甜蜜传递把「本 skill 内其他子技能」作为外来子技能传给目标（`DishInstance.TransferredSkills`），目标本次美食结算时随自身一并施加、生效一次、美食结束清除。除此之外结算逻辑零改动。设计语义见 [`docs/design/技能.md`](design/技能.md)。

#### TbSkill — 技能元信息

技能挂在菜品本体上，数量无上限。`termId` 非空时菜品详情额外展示该名词，并作为技能卡展示标题（无则不显示标题）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 技能ID（主键），通常命名为 `sk_<菜id>`，由 `TbDishBase.skills` 引用 |
| termId | string | 关联术语ID（可空）→ `TbTerm.id`；同时用作技能卡展示标题（术语名，空=无标题） |
| subSkills | string | 本技能独占的有序子技能ID列表（`\|` 分隔）→ `TbSubSkill.id`，顺序即运行时 `order`；第 N 项必须命名为 `<skillId>_N` |

#### TbSubSkill — 具体子技能（完整效果 + 占位符描述）

一行 = 一条完整效果。前提求值出 `count`，行为按 `效果 × count` 施加到 `actionScope`。参数不同即不同子技能。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 子技能ID（主键），固定命名为 `<skillId>_<从 1 开始的序号>`，如 `sk_cookie_1`、`sk_macaron_2`；每行只归属于一个技能 |
| trigger | [SkillTrigger](#skilltrigger) | 触发时机：`OnSettle` 在分数结算阶段执行；`OnServe` 在上菜后立即执行，只处理层数、金币、复制、甜蜜传递等运行时副作用 |
| condType | [SkillConditionType](#skillconditiontype) | 前提类型；决定 `raw count` 如何计算，`None` 表示无前提且固定触发 1 次 |
| condScope | [SkillScope](#skillscope) | 前提作用域；`Self/Adjacent/Row/Column/All/Before/After/Recipe/Category` 等枚举含义见下方字典 |
| condUnit | [CountUnit](#countunit) | 计数单位：`Instances` 按实例数并计入「视为食物数」；`Kinds` 按 `BaseId` 去重 |
| condMode | [CountMode](#countmode) | 计数模式：`Per` 返回原始数量；`Reach` 用 `condCompare + condThreshold` 判断是否达到；`Gate` 把正数转成 1、否则 0 |
| condCompare | [CompareOp](#compareop) | 比较符，主要给 `Reach`、`DishSize`、`RecipeCount` 使用；`None` 表示不比较 |
| condThreshold | int | 阈值；与 `condCompare` 组合，如 `DishSize + Gte + 3` 表示占格数大于等于 3 的菜 |
| condParam | string | 前提附加参数。常见格式：`self` 表示作用域计数包含自身；`settled` 表示 `SameKindInMeal` 读取本次品鉴已结算次数；`1x1`/`2x1` 表示 `ShapeMatch` 尺寸；`tiers:5\|15\|25` 表示阶梯阈值；`cap:3` 表示 `LayerCount` 封顶；`cake` 表示分类；`AddLayer`/`TransferSkills` 等行为枚举名表示 `SkillTypeCount` 统计带某类行为的菜 |
| actionType | [SkillActionType](#skillactiontype) | 行为类型；决定 `actionValue` 如何作用到目标或副作用 |
| actionScope | [SkillScope](#skillscope) | 行为作用域（目标）；`Category` 需配合 `actionParam=cat:xxx` 指定分类 |
| actionCount | int | 目标数量限制；`0`=全部目标，`>0` 表示最多取 N 个。结算阶段为确定性棋盘顺序取前 N；上菜阶段的甜蜜传递/复制由 `BattleSession` 用随机流落地 |
| actionValue | list,float | 行为数值，默认使用第一个值。`AddFlat/AddMultFlat/PermanentAddFlat/AddCountAs` 为加值；`AddMult/PermanentAddMult` 为倍率；`GrantGold` 为金币；`ExtraSettlement` 为次数；阶梯技能可填 0 并由 `actionParam=tiervals:...` 提供各档值 |
| actionParam | list,string | 行为参数。常见格式：`cat:cake` 指定分类目标或复制候选；`skilltype:TransferSkills` 过滤带某行为类技能的目标；`tiervals:1.5\|2.5\|5` 配合 `condParam=tiers:...`；`linear` 让 `AddMult` 按 `1+actionValue×count` 计算乘数；`mult` 表示 `AddLayer` 按当前层数乘法增长；`multfloor:5`/`floor:5` 表示乘法层数至少净增 5；`axis:rowcol` 让 `TriggerSweetTransfer` 同时检查同行和同列；`source:one-cell` 让 `AddCurrentMult` 汇总全场实际占 1 格食物的当前倍率（缺省则取自身） |
| isPassive | bool | 被动标记，用于描述/展示与部分预计算语义；如「技能额外触发」「视为N食物」填 `true` |
| signed | bool | 描述数值是否补正负号（加减类 true / 倍率类 false，沿用 `TagDescFormatter` 语义） |
| descTemplate | string | 占位符描述模板，见下方占位符表 |

**描述占位符**（由 `SkillDescComposer` 用合成后的规则回填）：

| 占位符 | 含义 |
| --- | --- |
| `{0}`/`{1}`… | `actionValue[i]`（signed=true 补正负号，倍率类配合模板里的 `×`） |
| `{cscope}`/`{ascope}` | 前提/行为作用域词：自身/周围/同行/同列/全场 |
| `{atargets}` | 行为作用域「X食物」前缀：Self→空串，其余→周围食物/同行食物/… |
| `{unit}` | 计数单位：个 / 种；`{thr}` 阈值；`{count}` 目标数 |
| `{countas}` | 本体「视为N个食物」总数（=`actionValue`+1，因 `dish_base.countAs` 恒为 1，子技能存增量 N-1） |
| `{targets}` | 甜蜜传递目标短语（作用域 + 目标数，0=所有） |
| `{tiers}` | `condParam` 里 `tiers:` 解析为 `3/5/8`；`{tiervals}` `actionParam` 里 `tiervals:` 解析为 `1.5/2.5/5` |
| `{floor}` | `actionParam` 里 `multfloor:`/`floor:` 的值；`{cat}` 分类名（cake→蛋糕） |

技能总描述 = 各子技能按 `subSkills` 顺序用其 `descTemplate` 回填后，用「；」拼接。

**技能字段联动速查**：

| 需求 | 关键字段写法 |
| --- | --- |
| 无条件加分 | `condType=None`，`condMode=Per`，`actionType=AddFlat`，`actionValue=分数` |
| 每有 N 个/种目标触发 | `condType=DishCount/SameDish/ShapeMatch/...`，`condMode=Per`，`condUnit=Instances/Kinds` |
| 达到阈值才触发 | `condMode=Reach`，`condCompare=Gte/Lte/Eq/Gt/Lt`，`condThreshold=阈值` |
| 布尔闸门 | `condMode=Gate`，前提 raw 大于 0 即触发一次；如 `PositionFilled`、`Edge` |
| 让作用域包含自身 | `condParam` 加 `self`；默认 `Adjacent/Row/Column/All` 统计时排除自身 |
| 阶梯技能 | `condParam=tiers:5\|15\|25`，`actionParam=tiervals:1.5\|2.5\|5`；满足第几档就取对应档值 |
| 指定分类 | 前提分类计数用 `condType=CategoryCount` + `condParam=cake`；行为目标分类用 `actionScope=Category` + `actionParam=cat:cake` |
| 指定行为类型 | `condType=SkillTypeCount` + `condParam=TransferSkills`，或 `actionParam=skilltype:TransferSkills` 过滤目标 |
| 欢乐蛋糕层数 | `actionType=AddLayer/ConsumeLayer` 操作全局层数；`condType=LayerCount` 读取当前层数，`condParam=cap:N` 可封顶 |
| 甜蜜传递 | `trigger=OnServe`，`actionType=TransferSkills`，`actionScope` 决定候选目标，`actionCount=0` 全部、`>0` 随机取 N 个 |

#### TbHiddenScoreCurve — 隐藏分曲线

按用途和周列表选择曲线，生成派生隐藏分与目标分。

菜品、道具、碎片隐藏分使用线性公式：`hidden = linearBase + weekCoeff * week + dayCoeff * currentDay + offset`。
目标分使用指数公式：`target = exp(expConstant + expWeekCoeff * week + expDayCoeff * currentDay + offset)`。

`offset` 来源按用途叠加：Food 本次行动临时修正 + 持有被动道具常驻修正；奖励槽生成时再额外叠加本槽 `normalHiddenOffset`。金币奖励固定使用 `TbGoldRewardCurve.gold_default`，也叠加 Food / 道具 / 槽三类金币隐藏分修正。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 曲线ID（主键） |
| purpose | [HiddenScorePurpose](#hiddenscorepurpose) | 用途：TargetScore/Dish/PassiveItem/Fragment/Gold |
| weekList | list<int> | 适用周数列表，空=不限 |
| linearBase | float | 线性公式常量项 |
| weekCoeff | float | 线性公式周数系数 |
| dayCoeff | float | 线性公式当周过去天数系数 |
| expConstant | float | 目标分指数公式常量 k0 |
| expWeekCoeff | float | 目标分指数公式周数系数 kWeek |
| expDayCoeff | float | 目标分指数公式当周过去天数系数 kDay |
| roundTo | int | 向上取整粒度 |

#### TbGoldRewardCurve — 金币奖励曲线

全局唯一金币奖励曲线，当前只保留 `gold_default`。按进度计算金币奖励中心值，再叠加 Food / 道具 / 奖励槽的金币隐藏分修正，最后按 `fluctuationPct` 上下浮动得到基础金币随机范围。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 曲线ID（主键） |
| baseValue | float | 金币奖励中心值基础值 |
| perWeek | float | 中心值每周递增值 |
| perDay | float | 中心值每行动轴天数递增值 |
| fluctuationPct | float | 上下浮动比例；例如 `0.2` 表示随机范围为中心值 `*0.8` 到中心值 `*1.2` |

#### TbBoss — Boss

Boss 节点按权重随机。`characterPool` 空=任意角色；`week=0` 任意周。

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| modifier | string | Boss 特殊机制标识（如 limit_serve/small_board） |
