# Balance Lab GM 使用手册

> 面向数值策划、系统策划和需要复盘具体 Build 的同学。
>
> 本文只介绍 Unity 中的 `Tools → Gourmet → Balance Lab`。网页“行动 GM”不在本文范围内。

## 1. 先记住这套标准流程

1. 打开 Unity，选择 `Tools → Gourmet → Balance Lab`。
2. 确认顶部配置状态为“已加载且与磁盘一致”。
3. 在“快速使用”页保留默认的“普通 + 高手”和 Seed `1001`。
4. 先跑“快速验证：每档 200 局”，确认没有程序异常、规则不支持或严重预算截断。
5. 再跑“正式报告：每档 5000 局”，完成后立即导出摘要 CSV 和完整 JSON。

快速验证默认共跑 400 局，适合检查规则和大方向；正式报告默认共跑 10000 局，用于形成数值结论。

> **重要：开始新任务会清空窗口中的上一份自动玩家报告。重要结果必须先导出。**

## 2. 打开前的准备

### 2.1 配置必须已生成

窗口打开时会自动读取：

```text
Assets/StreamingAssets/Config/*.json
```

顶部“生成配置”卡片应显示：

- “已加载且与磁盘一致”；
- 当前配置的 SHA-256 短哈希；
- JSON 文件数量；
- 本次加载时间；
- 数据源目录。

如果提示配置尚未生成或加载失败：

1. 运行 `GameConfig/gen.command`；也可以在项目目录执行 `bash GameConfig/gen.sh`。
2. 回到 Balance Lab，点击顶部“重新加载”。
3. 等状态恢复为“已加载且与磁盘一致”后再开始模拟。

### 2.2 不需要启动游戏

“快速使用”的自动玩家模拟：

- 不需要进入 Play 模式；
- 不需要手工摆 Build；
- 不读取或修改玩家存档；
- 不修改正式游戏的全局随机状态；
- 使用固定的 `all-unlocked-v1` GM 全解锁档；
- 跨局统计从零开始。

只有“读取当前游戏局面”这个高级快照功能需要进入 Play 模式并已开始一局。

## 3. 快速使用页

### 3.1 基础选项

| 选项 | 默认值 | 用途 |
| --- | --- | --- |
| 经营方向 | 当前配置列表第一项 | 选择本轮使用的经营方向/角色配置。 |
| 玩家水平 | 普通 + 高手 | 建议正式对比时保留双档。 |
| 基础种子 | 1001 | 每档依次使用 1001、1002、1003…… |
| 固定解锁档案 | all-unlocked-v1 | 按当前配置解锁全部目标，不能切换到玩家存档。 |
| 路线档案 | 仓库默认档案 | 控制自动玩家对普通、事件、利息和商店路线的倾向。 |

普通和高手使用相同的 Seed 区间。例如每档 200 局、基础 Seed 为 1001 时，两档都会使用 `1001～1200`，便于横向比较。

### 3.2 高级设置

日常使用可以保持收起。需要调整自动玩家假设时再展开。

| 选项 | 推荐默认值 | 含义 |
| --- | ---: | --- |
| 普通候选上限 | 24 | 普通玩家每次最多正式评估 24 个摆盘候选，并按温度 1.0 的 softmax 选择。 |
| 高手候选上限 | 64 | 高手玩家每次最多正式评估 64 个摆盘候选并选择最高排名。 |
| 单战正式预览预算 | 8000 | 每场战斗最多进行的无副作用正式预览次数。 |
| 利息保留本金 | 50 | 自动玩家为利息路线预留的金币。 |

点击“恢复推荐默认值”可以恢复整套自动玩家策略。

“候选上限”是刻意模拟玩家能力差异的有界策略，不是传统意义上的 Beam Width。调整这些值会改变自动玩家决策，但不会改变事件、商店和战斗规则本身的随机序列。

### 3.3 路线档案

仓库默认资源位于：

- [DefaultMetaAffinityCatalog.asset](../../Assets/GameMain/Content/Balance/DefaultMetaAffinityCatalog.asset)

如果档案缺失、没有覆盖当前配置内容或校验失败，运行按钮会被禁用。处理顺序：

1. 展开“高级设置”查看错误；
2. 点击“选择仓库默认档案”；
3. 如果配置新增了内容，点击“重建默认资源”；
4. 确认错误消失后再运行。

“重建默认资源”会直接覆盖仓库中的默认倾向资源和示例 Scenario，而且没有二次确认。自定义内容应先另存为其它资源；重建完成后还要人工复核路线语义并检查版本差异，因为默认倾向会按当前配置和道具 ID 规则重新生成。

## 4. 运行、进度与取消

### 4.1 两种运行规模

| 按钮 | 单档样本 | 默认双档总样本 | 建议用途 |
| --- | ---: | ---: | --- |
| 快速验证 | 200 | 400 | 配置改动后的冒烟、大方向检查、异常检查。 |
| 正式报告 | 5000 | 10000 | 正式分位数、版本对比和要求分建议。 |

正式报告可能需要数分钟到十几分钟，具体取决于机器、配置和每局长度。

### 4.2 进度条

窗口底部会显示：

- 已完成 trace / 总 trace；
- 每档已完成组数 / 每档目标数。

双档运行时，每完成一个玩家档位，总 trace 会增加；只有同一 Seed 的普通和高手都完成后，“每档”进度才进入下一组。

模拟采用编辑器分帧执行，运行期间窗口仍可操作，但不能重新加载配置或再启动另一个模拟任务。

### 4.3 正确取消方式

需要中止时，点击底部：

```text
取消并保留部分报告
```

取消会在下一次编辑器更新生效，并保留：

- 已完成的所有 trace；
- 当前被取消样本的结构化记录；
- 可继续导出的部分 CSV/JSON 报告。

部分报告不能用于正式推荐。

> **不要直接关闭 Balance Lab 窗口来取消。** 直接关闭只会丢弃正在运行的任务，不会生成可导出的部分报告。

## 5. 报告阅读顺序

建议固定按下面顺序阅读，避免只盯着 P30：

1. 报告是否完整、配置是否过期；
2. 程序异常和规则不支持是否为 0；
3. Boss 到达率；
4. Boss 到达者中的通过率；
5. P10/P30/P50/P90；
6. 日常营业、金币、预算截断、流派和路线分布；
7. 最后才决定是否采用“建议要求”。

## 6. 五类运行结果

| 结果 | 含义 | 是否影响正式结论 |
| --- | --- | --- |
| 通关 | 样本按正式规则完成整局。 | 正常有效样本。 |
| 正常战败 | 红心耗尽或正式 Game Over。 | 属于平衡结果，不是程序错误。 |
| 程序异常 | 运行时异常、无合法摆盘、预览预算耗尽、行动上限等。 | 只要大于 0，报告不可作为正式结论。 |
| 规则不支持 | 明确遇到当前模拟尚未支持的机制。 | 只要大于 0，推荐数值关闭。 |
| 用户取消 | 用户主动取消的实际 trace。 | 报告标为部分报告，推荐数值关闭。 |

“整局完成率”只统计真正完成整局的样本；正常战败不会混进程序异常。

“平均转向”表示每局主流派判定的平均切换次数，不是玩家点击次数。

## 7. 每周指标怎么读

### 7.1 Boss 到达和通过

- **Boss 到达率** = 该档该周到达 Boss 的样本数 / 该档实际局数。
- **Boss 通过率** = 通过 Boss 的样本数 / 已到达 Boss 的样本数。

通过率是条件通过率。必须与到达率一起看：如果只有少量强势样本活到 Boss，即使通过率很高，也不能说明全局难度合理。

### 7.2 P10/P30/P50/P90

这些分位数只统计 `BossReached = true` 的样本，不包含没活到 Boss 的局。

| 指标 | 解读 |
| --- | --- |
| P10 | 到达者中的低端表现。 |
| P30 | 偏保守的常态表现；约 70% 的到达者达到或超过该分数。 |
| P50 | 到达者的中位表现。 |
| P90 | 到达者中的高端表现。 |

无人到达 Boss 时，分位数和建议要求都显示 `—`。

> P30 不是“全部开局玩家的 70% 通过线”，而是“成功活到 Boss 的样本中约 70% 能达到的线”。

### 7.3 建议要求分

快速页的“建议要求”使用 Boss 到达样本的 P30，并且必须同时满足：

- 本档本周至少 30 条样本到达 Boss；
- 本档程序异常为 0；
- 本档规则不支持为 0；
- 本周摆盘预算截断率不超过 1%；
- 配置没有变化或过期；
- 请求样本全部完成；
- 任务没有被取消。

任何一项不满足，P 值可能仍保留供观察，但建议要求显示 `—`。

如果 Boss 到达率低于 50%，界面会提示幸存者偏差。此时即使达到 30 条并生成了 P30，也应先分析 Boss 前的死亡原因，不要机械采用建议值。

### 7.4 其它周指标

| 指标 | 含义 |
| --- | --- |
| 到达本周 | 成功进入该周的样本 / 该档实际局数。 |
| 日常营业 | 日常战斗通过次数 / 日常战斗次数，分母不是局数。 |
| 金币结余 | 到达该周样本的平均金币余额。 |
| 预算截断 | 该周耗尽正式摆盘预览预算的阶段比例。超过 1% 会关闭建议。 |
| 候选有界 | 合法候选超过普通 24 / 高手 64 上限的比例。属于预期的信息披露。 |
| 无合法方案 | 无法找到合法摆盘的比例，通常会形成程序异常。 |
| 流派比例 | 到达该周样本中，甜蜜、数量、蛋糕等主流派的构成。 |
| 路线比例 | 到达该周样本中，普通、事件、利息、商店路线的构成。 |

## 8. 常见警告及处理

| 警告 | 含义 | 建议动作 |
| --- | --- | --- |
| 没有样本到达本周 | 本周没有可统计阶段。 | 检查前一周难度、红心和经济。 |
| 没有样本到达 Boss | 无 Boss 分位数。 | 先处理 Boss 前死亡，不要填要求分。 |
| Boss 幸存者偏差 | 到达率低于 50%。 | 联合查看到达率、日常通过率和失败 Seed。 |
| Boss 样本不足 30 | 分位数可观察，但不能给建议。 | 增加样本或先提高到达率。 |
| 日常营业通过率低 | 普通战可能在 Boss 前大量消耗红心。 | 检查日常要求、初始 Build 与成长节奏。 |
| 候选有界 | 自动玩家按档位限制了候选数。 | 通常无需处理；这是正常策略。 |
| 存在预算截断 | 有阶段耗尽 8000 次预览预算。 | 若超过 1%，提高预算并重新跑正式报告。 |
| 无合法摆盘 | 当前盘面无法继续合法摆盘。 | 查看完整 JSON 的决策轨迹、餐桌和食谱。 |
| 运行异常 | 代码或模拟流程失败。 | 复制 Seed，导出 JSON，修复后重跑。 |
| 规则不支持 | 模拟遇到显式未支持机制。 | 补齐规则支持后重跑，不能绕过。 |
| 配置已过期 | 报告与磁盘配置哈希不一致。 | 重新加载配置并重跑。 |
| 采样未完成/用户取消 | 当前是部分报告。 | 只用于排查，不用于正式推荐。 |

## 9. 失败 Seed 与复现

报告底部会列出失败与异常 Seed：

- 窗口最多显示前 12 条；
- “复制失败 Seed 与原因”会复制全部失败记录；
- 每条包含玩家档位、Seed、最后到达周和原因；
- 通关 Seed 只进入上方汇总，不会出现在失败列表。

要复查一个自动玩家 Seed：

1. 先导出完整 JSON，保留原报告的配置、档案和策略哈希。
2. 记录玩家档位和目标 Seed。
3. 确认当前配置哈希、路线档案和策略参数与原报告一致。
4. 将“基础种子”设为目标 Seed，只选择对应玩家档位后重新运行；目标 Seed 会成为第一条样本。
5. 对照 JSON 中的逐周行动、奖励、购买、主动道具和每次摆盘决策。

同 Seed 只有在配置、经营方向、解锁档、路线档、玩家档位和策略版本一致时才应得到同一结果。

## 10. 导出报告

### 10.1 自动玩家报告

快速页提供：

- **导出摘要 CSV**：适合 Excel、版本对比、透视表和画图；
- **导出完整 JSON**：包含全部逐局 trace、失败原因、warning 和摆盘决策；
- **定位最近导出**：在文件管理器中打开最近导出的文件。

文件固定写入 Unity 项目根目录：

```text
BalanceReports/
```

实际仓库路径为：

```text
/Users/hcm-b0451/gourmetproject/GourmetProject/BalanceReports/
```

命名格式：

```text
balance-auto-{经营方向ID}-{基础Seed}-{时间}.csv
balance-auto-{经营方向ID}-{基础Seed}-{时间}.json
```

`BalanceReports/` 已被 Git 忽略。需要共享报告时应手动发送文件或上传到团队约定位置。

同一份报告重复导出相同格式会写入同一路径；CSV 和 JSON 扩展名不同，可以各保留一份。

### 10.2 CSV 和 JSON 各包含什么

CSV 每个“玩家档位 × 周”一行，包含：

- 配置、解锁档、路线档和策略版本；
- 请求数、实际数和五类结果统计；
- Boss 到达率、通过率和四个分位数；
- 有效时的建议要求分；
- 日常营业、金币、预算、流派和路线统计；
- 各类失败 Seed 和 warning code。

JSON 在这些摘要之外，还包含：

- 所有失败记录及完整原因；
- 每一局的逐周 trace；
- 行动、奖励、购买和主动道具记录；
- 每次摆盘的候选数、评估数、选择理由、预览分、空间评价和截断状态。

## 11. 配置变化与版本对比

Balance Lab 大约每秒检查一次磁盘配置。

配置变化后：

- 顶部会显示“磁盘内容已变化，等待重新加载”；
- 新模拟任务被禁用；
- 旧报告仍可查看和导出；
- 旧报告被标为过期；
- 分位数保留，但建议要求关闭。

正确流程：

1. 先导出当前重要报告；
2. 点击顶部“重新加载”；
3. 确认新的配置哈希；
4. 重新跑快速验证和正式报告；
5. 对比报告时同时核对配置、解锁档、路线档和策略版本。

不要把不同哈希的报告直接合并成同一组结论。

## 12. 高级快照分析

快速模拟用于评估“从开局到结束”的完整流程；快照分析用于回答“这个具体 Build 在这个时点能打多少分”。两者不能互相替代。

仓库提供可直接校验的示例：

- [ExampleBalanceScenario.asset](../../Assets/GameMain/Content/Balance/ExampleBalanceScenario.asset)

示例不会自动选中。进入非快速页后，需要把它拖入顶部的 `Balance Scenario` 字段，或自行新建 Scenario。

### 12.1 从实际游戏捕获

1. 进入 Play 模式并开始一局。
2. 打开 Balance Lab 的“快速使用”页。
3. 点击“读取当前游戏局面”。
4. 如果尚未选择 Scenario，按提示新建一个资源。
5. 当前局面会作为新的 Checkpoint 写入 Scenario。

捕获内容包括：

- 周、天、金币和要求分；
- 餐桌碎片和位置；
- 已摆食物、旋转、成长值、额外技能和风味；
- 装饰品与消耗品的 ID、等级和运行时 `StateJson`。

旧 Scenario 没有 `StateJson` 时会按空状态兼容。

快照捕获有三项边界需要特别注意：

- 不会自动填写 `BossDebuffId`，Boss 局面需要在高级编辑中手工补齐；
- 只有存在已摆食物的实际战斗盘面时，才会带出该战斗的要求分、蛋糕层和精确摆位；否则会按当前食谱做首个合法预览摆放；
- 它不是完整的 Run 存档复现，不包含红心、债务、时间轴、待领奖励和全部结算计数等状态。

此外，“读取当前游戏局面”不是严格零副作用：没有可直接读取的实际战斗盘面时，预览摆放会在当前正式局的随机服务中创建一个命名预览流。建议在可重载的测试局中捕获；如果要求捕获前后正式局 RNG 快照完全一致，应在已有实际摆盘的战斗中捕获，或捕获后重载该局。

### 12.2 复制阶段

选择当前 Checkpoint 后点击“复制为下一阶段”，再在“高级编辑”页修改周、天、金币、食物成长或道具，适合构造同一 Build 的成长曲线。

### 12.3 高级编辑

“高级编辑”页可以直接编辑 `BalanceScenario` 和 Checkpoint。完成后点击“验证全部 Checkpoint”。存在非法食物、重叠摆位、错误碎片、无效道具等问题时，单次和批量分析不会启动。Boss 实战快照还要特别检查并手工填写 `BossDebuffId`。

只有启用 `Perturbation` 后，下列字段才会参与随机扰动：

- 食物保留概率；
- 带权替代食物；
- 永久加分和倍率的随机范围。

### 12.4 单次分析

“单次分析”使用指定 Seed 对当前 Checkpoint 执行一次正式结算，显示：

- 总分；
- 金币变化；
- 每个食物的贡献；
- 正式 `ScoreLines` 的逐阶段计算过程。

适合验证某个技能、装饰品或结算顺序。

### 12.5 批量模拟

“批量模拟”支持：

- 当前 Checkpoint；
- 当前 Build 的全部阶段；
- 追加另一个 Build 到现有结果进行对比。

预览建议每阶段 1000 个样本，正式报告建议 10000 个。勾选 `AnalyzeContribution` 的组件会进行同 Seed 的边际贡献分析，最多使用 1000 个样本以控制耗时。

结果包含均值、标准差、CV、P10/P25/P50/P75/P90、最大值、当前通过率和组件边际贡献。

### 12.6 目标美味值反推

该页使用快照批量结果反推：

- 普通：P30；
- 困难：P50；
- 挑战：P75。

结果会按目标美味值曲线的 `RoundTo` 向上取整。

注意：这是“固定 Build 快照”的三档建议，与快速页“完整自动玩家流程的 Boss P30”是两个不同口径。

快照报告的 CSV/JSON 会弹出保存位置选择框，不会自动写入 `BalanceReports/`。

## 13. 常见问题

### 运行按钮是灰色的

依次检查：

1. 配置是否加载成功；
2. 磁盘配置是否发生变化；
3. 路线档案是否缺失或校验失败；
4. 是否已有自动模拟或快照任务在运行。

### 全部样本都正常战败，是不是 GM 坏了

不是。正常战败是正式规则产生的有效平衡结果。重点继续查看死亡周、Boss 到达率、日常营业通过率、金币结余和失败 Seed。

### 有 P30，但建议要求仍是横杠

常见原因：

- Boss 到达样本不足 30；
- 有程序异常或规则不支持；
- 预算截断率超过 1%；
- 配置已变化；
- 任务被取消或样本没有跑齐。

### “候选有界”比例很高

这通常是正常现象，表示合法摆位很多，自动玩家按普通 24 / 高手 64 的能力上限取样评估。它本身不会使建议失效。

### 预算截断率超过 1%

提高“单战正式预览预算”并重跑。不要直接采用旧报告的建议要求；同时检查是否存在异常复杂的餐桌或食谱组合。

### 看到程序异常或规则不支持

1. 不要采用推荐数值；
2. 点击“复制失败 Seed 与原因”；
3. 导出完整 JSON；
4. 保留配置、档案和策略哈希；
5. 交给程序定位并在修复后重新跑完整报告。

### 已经点了取消，但为什么请求数和实际数不同

这是预期行为。只统计真正生成 trace 的样本；尚未启动的局数由“请求数 - 实际数”体现，不会伪装成用户取消 Seed。

## 14. 正式出数检查清单

发布或提交数值结论前逐项确认：

- [ ] 顶部配置状态为“已加载且与磁盘一致”。
- [ ] 使用约定的经营方向、玩家档位和基础 Seed。
- [ ] 路线档案通过严格校验。
- [ ] 先完成每档 200 局快速验证。
- [ ] 程序异常为 0。
- [ ] 规则不支持为 0。
- [ ] 预算截断率不超过 1%。
- [ ] 目标周至少有 30 条样本到达 Boss。
- [ ] 已结合 Boss 到达率解读 P30，没有忽略幸存者偏差。
- [ ] 正式样本全部完成且没有取消。
- [ ] 已导出摘要 CSV 和完整 JSON。
- [ ] 报告中记录了配置、解锁档、路线档和策略哈希。
- [ ] 开始下一轮任务前，上一份重要报告已保存。
