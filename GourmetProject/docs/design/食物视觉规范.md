# 食物视觉规范

本规范用于食物棋盘 Sprite、商店预览、食谱、奖励和评审打样。通常只重绘图片；经审阅确认替换食物时，显示名、英文 ID、技能 ID、变体和图片必须同步修改，数值与机制保持不变。

## 画风锁定（不可随评语改变）

- 唯一画风母版为 `Art/FoodVisualSamples/storybook_full/final/matcha_cake.png`（抹茶蛋糕）。所有正式食物和重做图必须先对照该图。
- 固定表现为暖色绘本半厚涂：细到中等、粗细有变化的深棕轮廓；柔和自然的体积；克制的手绘笔触和食物材质；温暖、协调的明暗。
- 禁止漂移为扁平矢量、均匀粗描边图标、纯色块赛璐璐、写实照片或高光塑料感。
- “更卡通”“减少细节”“更和谐”等评语只调整造型、装饰数量、纹理密度和配色关系，不改变上述轮廓、上色、体积与材质语言。
- 生成时母版始终作为第一参考图；其他旧图只能用于说明甜品原型或构图，不能继承其画风。
- 每轮交付前必须同时检查：与抹茶蛋糕的画风一致性、格子覆盖率、现实甜品可识别性。任何一项不合格都不能进入审阅表或正式资源。

## 四类视觉语言

| 类型 | 第一眼识别信号 | 内部甜品范围 |
|---|---|---|
| 蛋糕流 | 蛋糕层、蛋糕胚、裱花、切面、底托 | 名称必须包含“蛋糕” |
| 甜蜜传递流 | 糖纸、锡纸、棒签、糖晶、巧克力材质 | 糖果、巧克力及其明确制品 |
| 东方点心流 | 糕、酥、糯米点心、青瓷或竹托、中式甜品碗 | 视觉归类；程序仍使用“份数”机制 |
| 通用食物 | 现实甜品自身轮廓和中性器皿 | 不套用其他三类的专属包装信号 |

双流派只设置一个主视觉：糖霜蛋糕以蛋糕为主、糖饰为辅；慕斯蛋糕以蛋糕为主、中式分份托为辅；巧克力棒以糖果包装为主、分段结构为辅。

## 命名规则

- 只使用现实中已有、中文语境容易识别的甜品名。
- 名称不超过5个汉字；不同食物不得重名。
- 不使用宴席甜饭、原料、包装名或需要额外解释才知道是甜品的名称。
- 蛋糕流主流派名称必须含“蛋糕”；甜蜜传递流主流派必须是糖果或巧克力。

本轮32项改名：

- 蛋糕01–04：年轮蛋糕、城堡蛋糕、红丝绒蛋糕、抹茶蛋糕。
- 传递01–04：牛轧糖、跳跳糖、松露巧克力、酒心巧克力。
- 份数01–04：山楂糕、驴打滚、绿豆糕、蛋黄酥。
- 通用01–08：焦糖布丁、冰淇淋、苹果酥、水果挞、草莓圣代、红豆冰棒、水果刨冰、椰奶冻。
- 既有食物：拿破仑蛋糕、蜂蜜蛋糕、桂花糕、竹筒糕、红糖发糕、马拉糕、双皮奶、巧克力威化、蜂窝糖、生巧克力、奶油泡芙、馒头。

## 格子与构图

- 每格原生尺寸为512像素，文件尺寸严格等于形状包围盒。例如2×2为1024×1024，3×2为1536×1024。
- 主体自然跨入每个 `X` 格；每个有效格内的可见主体面积不得低于该格的35%，不要求主体与格子包围盒等比例。
- `.` 格必须完全透明，Alpha覆盖率低于1%。
- 保持现实比例，不拉伸，不用多个相同造型复制填充格子。
- 同流派且同格子尺寸的食物不得重复“主轮廓 + 器皿”组合。
- 禁止拟人化、五官、肢体、文字、品牌标志、外部投影和地面接触影。

## 材质与差异化

- 蛋糕流优先用层数、切面、胚体比例、裱花走势和底托形状区分。
- 甜蜜传递流优先用糖纸折角、棒签方向、糖晶、夹心断面、巧克力光泽与分段方式区分。
- 东方点心流优先用糕、酥、糯米和甜品汤水的材质差异，器皿从青瓷、竹托、中式纸托中择一。
- 通用食物使用白瓷、烘焙纸托或符合原型的中性器皿，不借用流派纹样。

## 四套画风打样

每套使用相同六个食物：抹茶蛋糕、黑森林蛋糕、松露巧克力、巧克力威化、蛋黄酥、双皮奶。画风为厚描边赛璐璐、软陶立体、暖色绘本半厚涂、分层纸雕。

打样放在 `Art/FoodVisualSamples`，不覆盖正式资源。每张正式候选图均为独立透明PNG；评审板中的名称和格子示意不进入 Sprite。选定画风后才重绘正式食物和隐藏馒头。

## 正式资源导入

- 文件名继续使用 `baseId`，替换图片时保留现有 `.meta`。
- PNG透明背景，100 PPU，双线性过滤，关闭MipMap。
- 验收棋盘、商店、食谱、奖励界面，并重点检查1×3、3×1、2×3、3×3和非矩形食物。
