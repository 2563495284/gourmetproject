# 行动系统（薄壳行动 + 类别/奖励逐卡随机）

> 拆分自 [游戏设计总览](../游戏设计.md)。相关：[时间轴](./时间轴.md)、[事件](./事件.md)、[专有名词解释](./专有名词解释.md)。
>
> 本文是「原子行动」的唯一权威定义。时间轴节点、事件、Boss、利息、商店等**全部**是原子行动的具体形态。

## 核心模型

游戏中一切「会发生的事」都是一个**原子行动（Action）**，它是最基础、不可再拆的行为单元。原子行动在**表现上一致**（统一以卡片呈现），在**执行上按行为分派**（每种行为走自己的结算逻辑，便于扩展）。

原子行动由两个**正交维度**描述：

- **来源（Source）**：这个行动是怎么进入游戏的。
  - `Placed`：放置在时间轴的某个节点上，到达该天时**自动触发**（Boss、利息、商店、剧情节点等）。
  - `Random`：推进日程时从行动组随机出一组供玩家 **n 选 1**（日常推进）。
  - `Rest`：无可选行动时的**兜底休息**，消耗固定天数。
- **行为（Behavior）**：这个行动做什么、如何结算。单一枚举 `Food / Event / Reward / Negative / Shop / Interest`。

## 行动 = 薄壳，具体内容在明细表

`TbAction` 只是一层**薄壳分派器**：它只保存「这是什么行为 + 指向哪张明细/少量参数」，不承载具体内容。具体内容各归各的明细表，和事件同构：

| 行为 Behavior | 卡面/结算来源 | 明细表 |
|---|---|---|
| Food | 经营挑战明细（含 Boss） | `TbFood`（`foodId` 1:1 关联；Food 行为且 `foodId` 为空时作为 星级评鉴槽执行随机） |
| Event | 交互多选项事件 | `TbEvent`（Event / Reward / Negative 合并池）+ `TbEventOption` |
| Reward | 即时奖励事件 | `TbEvent`（`eventTypes` 包含 Reward）+ `TbEventOption` |
| Negative | 负面事件 | `TbEvent`（`eventTypes` 包含 Negative）+ `TbEventOption` |
| Shop | 打开商店 | 无（直接结算） |
| Interest | 利息结算 | `TbGameBase` 的 `interestThreshold` / `interestGoldPer` |

**公共三字段 `preconditions` / `weight` / `repeatable` 下放到明细表**（`TbFood` / `TbEvent`），不在行动上。候选行动的可用性由其关联明细决定。

### TbAction 字段（薄壳）

| 字段 | 说明 |
|---|---|
| id | 行动唯一 ID |
| name / desc | 卡面兜底文本（Food 由 `TbFood` 覆盖、Event 由抽到的 `TbEvent` 覆盖） |
| behavior | 行为类型 |
| foodId | Food：关联的具体食物 `TbFood.id`（1:1）；空且 behavior=Food 时表示 星级评鉴槽 |
| min_cost_days / max_cost_days | 本次行动耗时随机范围（`Random` 来源生效；`Placed` 节点通常为 0） |

## 行为类型（Behavior）

| 行为 | 说明 | 结算入口 |
|---|---|---|
| Food | 经营挑战。日常营业/火热营业/星级评鉴差异全在 `TbFood`（目标美味值倍率、金币曲线、奖励包、隐藏分、debuff）；星级评鉴 = `actionKind=Feast` 的食物行，普通食物也可带 debuff | 读 `TbFood` 进入经营挑战；星级评鉴槽先从池抽一条星级评鉴食物 |
| Event | 交互事件，携带**多个选项分支**，玩家在事件内部再做一次分支选择 | 从 Event 池随机一个具体事件，展示文本与选项，执行所选分支结果 |
| Reward | 即时奖励 | 从 Reward 池随机一个奖励事件，单选项自动结算 |
| Negative | 负面效果 | 从 Negative 池随机一个负面事件，单选项自动结算 |
| Shop | 打开商店购买、编辑食谱、删除食物 | 打开商店 |
| Interest | 利息结算：每满 N 金币获得若干金币（受封顶限制） | 直接结算金币 |

> Event / Reward / Negative 三种行为同构：都是「从 `eventTypes` 命中的事件池随机一个具体事件再结算」，只是池不同、表现不同。一个事件可用 `Event|Reward` 同时加入多个池；第一项是主分类，决定权重加成与保底语义。单选项事件=自动结算（奖励/负面/即时），多选项=玩家分支选择。

> 注意区分两种「选择」：
> - **行动 n 选 1**：`Random` 来源下，玩家在多个原子行动之间选一个来推进日程。
> - **事件选项分支**：Event 行动内部，玩家在该事件的多个结果分支间选一个。

## 随机来源：行动数洗牌袋 + 类别/奖励逐卡随机

`Random` 来源按以下顺序生成一组 n 选 1：

```text
行动数洗牌袋（2 张票×2、3 张票×1）
  → 每个槽位先抽类别（日常 / 火热 / 事件）
  → 营业类别再抽奖励（五种 RewardKind）
  → 用 Food.actionKind + Food.rewardKind 唯一定位行动
```

- 行动数规则来自 `TbActionChoiceCountRule`。每周按整数权重装票并洗牌，袋空重装；换周清空，重掷也消费一张票。
- 类别来自 `TbActionCategoryRule`：`Daily=1`、`Hot=2`、`Event=3`。日常/火热由 `TbFood.actionKind=Normal/Super` 推导；事件由 `TbAction.behavior=Event` 推导。星级评鉴和其它行为不进入日常随机池。
- 奖励来自 `TbActionRewardRule`，键直接复用 `TbFood.rewardKind`：装饰品、餐桌格、强化箱、调整单、金币。事件奖励固定为未知，不进入奖励权重、保底或计数。
- 类别和奖励都按本周所有已成功生成候选卡的累计序号执行：先在低于下保底的合法候选中抽，再看上保底，最后在全部合法候选中按本周权重抽。周/候选序号越界或值为负数表示不限制；周权重越界沿用最后一周。
- 屏蔽先于保底：同组最多一个事件；同类别已经出现的奖励不可再次出现，不同类别可使用相同奖励。被屏蔽的到期保底不会失效，会在后续合法候选卡继续参与。
- 类别和奖励只在成功定位具体行动后计数。重掷会生成全新组，旧组虽被覆盖但已经产生的候选卡仍计入本周累计。
- 街角路牌作用于事件类别、霓虹招牌作用于火热类别：类别权重与上下保底目标都乘以 `1+n%`，保底目标四舍五入；`-1` 保持不限。

运行态保存所属周、候选卡序号、类别/奖励累计、行动数袋剩余顺序和生成组序号。行动选择界面的 pending 候选仍用于重开/读档复用，因此不会重复抽取或计数；重掷不复用 pending，而是正常生成并累计新组。每张卡仍按行动 `min/maxCostDays` 随机本次耗时；若无可选行动，`Rest` 兜底消耗 1 天。

## 放置来源：时间轴节点

`Placed` 来源即时间轴节点。节点只保存 `{ day, action_id }`，到达该天时把节点引用的原子行动构造成执行上下文并**走与普通行动完全相同的执行路径**。是否需要「二次随机」（如 Boss 从池抽、Event 随机具体事件）由对应行为在执行时内部处理。详见 [时间轴](./时间轴.md)。

## 行动执行

无论来源如何，执行统一按 `behavior` 分派到对应处理器（handler），产出 `ActionOutcome` 交编排层做异步表现：

```text
确定原子行动（Random 玩家选择 / Placed 节点触发 / Rest 兜底）
  ↓
创建 ActionExecutionContext（来源、稳定随机组键、整局序号、本次耗时）
  ↓
按 behavior 分派 handler：
   Food     → 读 TbFood / 星级评鉴槽抽 Boss，产出经营挑战
   Event/Reward/Negative → 产出「需事件表现」，编排层从对应池抽具体事件并结算
   Shop     → 打开商店
   Interest → 直接结算利息
  ↓
玩家明确结算时 Commit：按 min/max 随机出的耗时推进天数、记录步数与不可重复
  ↓
结算经过的时间轴节点 → 下一次 n 选一 / 进入下一周 / 结算胜负
```

新增一种行为 = 新增枚举值 + 一个 handler + 明细表配置，**不改动编排层**，这是「易扩展」的落点。
