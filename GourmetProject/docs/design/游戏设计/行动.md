# 行动系统（薄壳行动 + 行为明细表 + 两层行动组）

> 拆分自 [游戏设计总览](../游戏设计.md)。相关：[行动轴](./行动轴.md)、[事件](./事件.md)、[专有名词解释](./专有名词解释.md)。
>
> 本文是「原子行动」的唯一权威定义。行动轴节点、事件、Boss、利息、商店等**全部**是原子行动的具体形态。

## 核心模型

游戏中一切「会发生的事」都是一个**原子行动（Action）**，它是最基础、不可再拆的行为单元。原子行动在**表现上一致**（统一以卡片呈现），在**执行上按行为分派**（每种行为走自己的结算逻辑，便于扩展）。

原子行动由两个**正交维度**描述：

- **来源（Source）**：这个行动是怎么进入游戏的。
  - `Placed`：放置在行动轴的某个节点上，到达该天时**自动触发**（Boss、利息、商店、剧情节点等）。
  - `Random`：推进日程时从行动组随机出一组供玩家 **n 选 1**（日常推进）。
  - `Rest`：无可选行动时的**兜底休息**，消耗固定天数。
- **行为（Behavior）**：这个行动做什么、如何结算。单一枚举 `Food / Event / Reward / Negative / Shop / Interest`。

## 行动 = 薄壳，具体内容在明细表

`TbAction` 只是一层**薄壳分派器**：它只保存「这是什么行为 + 指向哪张明细/少量参数」，不承载具体内容。具体内容各归各的明细表，和事件同构：

| 行为 Behavior | 卡面/结算来源 | 明细表 |
|---|---|---|
| Food | 美食/战斗明细（含 Boss） | `TbFood`（`foodId` 1:1 关联；Food 行为且 `foodId` 为空时作为 Boss 槽执行随机） |
| Event | 交互多选项事件 | `TbEvent`(eventType=Event) + `TbEventOption` |
| Reward | 即时奖励事件 | `TbEvent`(eventType=Reward) + `TbEventOption` |
| Negative | 负面事件 | `TbEvent`(eventType=Negative) + `TbEventOption` |
| Shop | 打开商店 | 无（直接结算） |
| Interest | 利息结算 | `TbGameBase` 的 `interestThreshold` / `interestGoldPer` |

**公共三字段 `preconditions` / `weight` / `repeatable` 下放到明细表**（`TbFood` / `TbEvent`），不在行动上。小组成员的可用性由其关联明细决定。

### TbAction 字段（薄壳）

| 字段 | 说明 |
|---|---|
| id | 行动唯一 ID |
| name / desc | 卡面兜底文本（Food 由 `TbFood` 覆盖、Event 由抽到的 `TbEvent` 覆盖） |
| behavior | 行为类型 |
| foodId | Food：关联的具体美食 `TbFood.id`（1:1）；空且 behavior=Food 时表示 Boss 槽 |
| min_cost_days / max_cost_days | 本次行动耗时随机范围（`Random` 来源生效；`Placed` 节点通常为 0） |

## 行为类型（Behavior）

| 行为 | 说明 | 结算入口 |
|---|---|---|
| Food | 美食挑战。普通/困难/Boss 差异全在 `TbFood`（目标分倍率、金币曲线、奖励包、隐藏分、debuff）；Boss = `isBoss=true` 的美食行，普通食物也可带 debuff | 读 `TbFood` 进入美食战斗；Boss 槽先从池抽一条 Boss 美食 |
| Event | 交互事件，携带**多个选项分支**，玩家在事件内部再做一次分支选择 | 从 Event 池随机一个具体事件，展示文本与选项，执行所选分支结果 |
| Reward | 即时奖励 | 从 Reward 池随机一个奖励事件，单选项自动结算 |
| Negative | 负面效果 | 从 Negative 池随机一个负面事件，单选项自动结算 |
| Shop | 打开商店购买、编辑菜谱、删除菜品 | 打开商店 |
| Interest | 利息结算：每满 N 金币获得若干金币（受封顶限制） | 直接结算金币 |

> Event / Reward / Negative 三种行为同构：都是「从对应 `eventType` 分类的事件池随机一个具体事件再结算」，只是池不同、表现不同。单选项事件=自动结算（奖励/负面/即时），多选项=玩家分支选择。

> 注意区分两种「选择」：
> - **行动 n 选 1**：`Random` 来源下，玩家在多个原子行动之间选一个来推进日程。
> - **事件选项分支**：Event 行动内部，玩家在该事件的多个结果分支间选一个。

## 随机来源：两层行动组

`Random` 来源的 n 选 1 由**大组 → 小组**两层加权随机决定：

```text
 action_schedule_rule（每周保底窗口: activeWeeks + 周内步窗口[minRunStep,maxRunStep] + minCount/maxCount）
        │
   大组 LargeGroup（ruleIds + fallbackWeights[周-1] 权重）
        │  按 小组.weight 选 1 个小组
   小组 SmallGroup（固定成员）
        │
   小组成员（经可用性过滤）= 本次 n 选一
```

- **小组 SmallGroup**：通过 `actionIds` 内嵌固定行动成员，成员即本次展示的 n 张卡（最多 3 张）。`weight` 供所属大组按权重挑选。
- **大组 LargeGroup**：通过 `smallGroupIds` 内嵌多个小组。大组由自身 `fallbackWeights`（按当前周-1 取，越界取最后一个）权重随机；用 `ruleIds` 声明参与哪些日程规则（规则不再持有候选组列表）。
- **日程规则只做「每周保底」**：`minRunStep`/`maxRunStep` 是**周内行动步序号**窗口（`maxRunStep` 必须为有限上限 &gt; 0），`activeWeeks` 决定生效周，`minCount`/`maxCount` 与计数**每周独立、周初清零**。规则不再抢占/前置某大组，只保证窗口内至少出现 `minCount` 次。窗口之外（本周步数超过所有规则窗口上限）不受规则约束，纯按权重遅延生成，天然适配「周长度随玩家选择变化」。

每周大组计划生成（**周开始时一次性预排本周**）：

1. **散布保底**：收集本周生效规则（`activeWeeks` 命中 + 前置条件满足），按优先级降序，把每条规则的 `minCount` 名额随机落在其周内窗口 `[minRunStep,maxRunStep]` 的空位上，落位大组从「声明了该规则的大组」里按 `fallbackWeights[周-1]` 权重挑选（尊重 `maxCount` 上限）。
2. **权重充填**：剩余空位按 `fallbackWeights[周-1]` 加权随机填充，尊重各规则 `maxCount`，并避免与前/后相邻大组重复。
3. 窗口（本周计划长度）之外的步数：仅按权重遅延生成，与上一格避免重复。
4. 运行态保存已生成的大组序列、本周计划与整局行动序号，读档后不重抽已定部分；跨周时自动为新周重建计划。

每次打开行动选择界面：读取当前整局行动序号对应的大组 → 按小组权重选小组 → 小组成员经可用性过滤后作为 n 选一（每张卡按行动 `min/max_cost_days` 随机本次耗时）。若无可选行动，`Rest` 兜底消耗 1 天。

## 放置来源：行动轴节点

`Placed` 来源即行动轴节点。节点只保存 `{ day, action_id }`，到达该天时把节点引用的原子行动构造成执行上下文并**走与随机行动完全相同的执行路径**。是否需要「二次随机」（如 Boss 从池抽、Event 随机具体事件）由对应行为在执行时内部处理。详见 [行动轴](./行动轴.md)。

## 行动执行

无论来源如何，执行统一按 `behavior` 分派到对应处理器（handler），产出 `ActionOutcome` 交编排层做异步表现：

```text
确定原子行动（Random 玩家选择 / Placed 节点触发 / Rest 兜底）
  ↓
创建 ActionExecutionContext（来源、大组、整局序号、本次耗时）
  ↓
按 behavior 分派 handler：
   Food     → 读 TbFood / Boss 槽抽 Boss，产出美食战斗
   Event/Reward/Negative → 产出「需事件表现」，编排层从对应池抽具体事件并结算
   Shop     → 打开商店
   Interest → 直接结算利息
  ↓
玩家明确结算时 Commit：按 min/max 随机出的耗时推进天数、记录步数与不可重复
  ↓
结算经过的行动轴节点 → 下一次 n 选一 / 进入下一周 / 结算胜负
```

新增一种行为 = 新增枚举值 + 一个 handler + 明细表配置，**不改动编排层**，这是「易扩展」的落点。
