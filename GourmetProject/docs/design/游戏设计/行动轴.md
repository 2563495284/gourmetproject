# 阶段与行动轴

> 拆分自 [游戏设计总览](../游戏设计.md)。相关：[行动系统](./行动.md)、[事件](./事件.md)、[美食与 Boss](./美食与Boss.md)。
>
> 行动轴节点不再是独立的「节点事件」类型，而是**放置来源（`Source=Placed`）的原子行动**。节点只负责「在哪一天放哪个行动」，行为本身与随机行动共用同一套定义与执行路径，见 [行动系统](./行动.md)。

## 行动轴

一周是一条行动轴。行动轴配置包含：

| 字段 | 说明 |
|---|---|
| timeline_id | 行动轴 ID |
| base_length_days | 默认长度，通常为 7 天 |
| nodes | 放置节点列表 |

行动轴随机规则：

1. 当前周从 `Week.timelineIds` 读取候选行动轴，并用 `Week.timelineWeights` 提供对应权重。
2. 根据角色 `timelinePool` 额外筛选可用行动轴。
3. 按 Week 中配置的权重随机一条。
4. 运行态只保存当前行动轴 ID 和天数游标，读档时按配置重建节点。

## 节点（放置的原子行动）

节点是「在某一天放置一个原子行动」的引用，不再有独立的节点类型枚举：

| 字段 | 说明 |
|---|---|
| id | 节点 ID |
| timeline_id | 所属行动轴 |
| day | 触发天（整天） |
| action_id | 引用的原子行动 |

常见放置行动即原「节点事件」，现统一为原子行动的行为：

| 原节点类型 | 现行为 | 说明 |
|---|---|---|
| Boss | `Food`（`foodId` 为空的 Boss 槽） | 执行时从 `TbFood` 中 `isBoss` 的美食候选不放回随机一条；取光后重置候选，机制随该 Boss 美食 |
| 利息 | `Interest` | 每满 N 金币获得若干金币 |
| 商店 | `Shop` | 进入商店 |
| 事件 | `Event` | 执行时从 Event 事件池随机具体事件 |

「是否二次随机」（Boss 从 `TbFood` 的 Boss 候选中抽、Event 从 `TbEvent` 抽具体事件）由对应行为在执行时内部决定，节点本身只引用一个 `action_id`。

## 节点结算规则

- 行动从 `prevDay` 推进到 `newDay` 时，触发 `prevDay < node.day <= newDay` 的未触发节点。
- 同一次行动跨过多个节点时按 `day` 升序结算：依次把每个节点引用的原子行动构造执行上下文，走与随机行动**相同**的执行路径。
- 节点触发后写入已触发集合（统一到已用行动记录），读档后不重复结算。
