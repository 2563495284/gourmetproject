# 上菜与结算

> 拆分自 [游戏设计总览](../游戏设计.md)，对应原文档「11. 上菜与结算」。相关：[棋盘](./餐桌.md)、[食物](./食物.md)、[装饰品和消耗品](./装饰品与消耗品.md)、[食物与 Boss](./食物与星级评鉴.md)。

## 上菜

1. 进入美食战斗并完成 Boss、饼干保底、装饰品等配置后，系统用独立的战斗序列随机流一次性生成本场固定出菜优先序列；同一主种子、battle key、食谱与战斗配置会得到相同序列，不受普通 `combat` 流已经消费多少随机数影响。
2. 普通食谱条目按引用身份执行不放回加权排序，权重为 `max(1, 食物初始占格数)`。计划每一步先应用饼干保底，再应用鲜菜严格优先，最后才在候选内按占格权重抽取。每个普通条目只进入序列一次。
3. Boss 额外插菜会在计划阶段按其窗口规则生成固定位置，合入 0 号自动出菜序列；它不消耗食谱条目，但会参与计划阶段的连续饼干计数。系统效果触发的额外上菜会忽略这类仅限自动出菜的插入 token。
4. 真正出菜时，每次都从剩余固定序列头部开始做一次有界扫描，并按当前餐桌实时计算旋转与合法落点。放不下的条目只在本次扫描中跳过，保留在原位；选中的普通条目才从序列和本场食谱副本中移除。
5. 若本次扫描所有条目都放不下，则返回 `NoFittingDish`，不移除条目、不推进游标、也不再消耗序列随机数。清桌、移除食物、旋转到临时桌等盘面变化后会重新从头扫描，因此此前跳过的较早条目一旦可放，会优先恢复上菜。
6. 食物的可用朝向继续遵循实时风味规则；默认允许 90 度旋转，「麻」则按其固定旋转规则寻找落点。

## 技能与风味结算

1. 若无特殊效果，按照从上到下、从左到右确立所有棋盘格的结算顺序。
2. 多个棋盘格为同一个食物时，只在第一次结算该食物的技能与风味，格子标签可以结算多次。
3. 单道食物内的结算顺序：先结算全部技能，再结算风味，最后结算所占格子的格子标签。

## 分数结算

若无特殊标签，按照从上到下、从左到右的顺序，把所有分数加合作为总分数。消耗品、装饰品、标签和 星级评鉴机制可以在最终结算前追加加法、乘法或达标修正。
