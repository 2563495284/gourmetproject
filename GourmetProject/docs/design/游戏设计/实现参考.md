# 实现参考

> 拆分自 [游戏设计总览](../游戏设计.md)，合并原文档「15. 推荐工程模块拆分」「16. 推荐核心状态结构」「17. 关键实现规则」。

## 推荐工程模块拆分

```text
GameRun
  - 管理单局生命周期状态
  - 保存经营方向、周数、天数、金币、装饰品和消耗品、食物、餐桌格和触发记录

ActionRandomService
ActionScheduleService
  - 生成并持久化整局行动组序列
  - 按周内已出现次数依次处理最小保底、最大保底与自由权重随机
  - 从当前行动组内生成 n 选一行动（最多 3 个）与行动选择快照

ActionRandomService
  - 提供组内候选筛选、前置条件、不可重复行动过滤和权重随机工具
  - 不再从全局行动池直接生成主循环行动选择

ActionExecutor
  - 执行行动结果
  - 推进天数
  - 修改局外状态

TimelineService
  - 初始化时间轴
  - 推进时间轴
  - 检测经过节点
  - 提供节点数据

EventService
  - 事件随机
  - 展示事件
  - 执行事件选项结果

BossService
  - 根据节点池、周和解锁条件筛选 Boss
  - 按权重随机 Boss

FoodChallengeService / BattleForm
  - 处理经营挑战
  - 判断分数是否达标
  - 发放奖励或触发失败

ShopService
  - 根据隐藏分刷新商品
  - 处理购买、编辑食谱、删除食物

RewardService / RewardGranter
  - 统一发放金币、食物、装饰品和消耗品、餐桌格等奖励

SettlementService
  - 生成通关或失败结算数据
  - 生成新解锁内容展示
```

## 关键实现规则

1. 文档和实现以“7 天游标 + 行动数洗牌袋 + 类别/奖励逐卡随机 + 组内 n 选一（2–3 个）”为主口径。
2. 行动数每周按整数票洗牌消费；类别和奖励计数按周、按已生成候选卡独立累计，均按下保底、上保底、自由权重三个阶段抽取。
3. 行动随机必须先过滤事件/同类别奖励重复、行动可用性和唯一映射，再执行保底；被屏蔽的保底顺延。
4. 行动执行后先推进天数，再检查经过的时间轴节点。
5. 如果一次行动经过多个节点，应按节点在时间轴上的顺序依次结算。
6. 经营挑战未达标时按规则扣除红心，红心归零则游戏失败。
7. 非最终周星级评鉴达标，立即进入下一周。
8. 最终周星级评鉴达标，立即游戏通关。
9. 商店商品根据隐藏分和权重随机。
10. 删除食物需要扣除金币。
11. 结算时展示游戏结果、局内指标和新解锁内容。
