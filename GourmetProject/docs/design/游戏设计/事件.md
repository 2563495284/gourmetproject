# 事件（TbEvent 明细表）

> 拆分自 [游戏设计总览](../游戏设计.md)。相关：[行动系统](./行动.md)、[行动轴](./行动轴.md)。
>
> 事件不是独立顶层系统，而是三种「事件类行为」（`Event` / `Reward` / `Negative`）共用的**明细表 `TbEvent`**。行动通用字段、来源、执行路径见 [行动系统](./行动.md)。

## 定位

`Event` / `Reward` / `Negative` 三种行为的原子行动都是**薄壳**：执行时从 `TbEvent` 里按 `eventType` 分类池随机抽一个具体事件再结算。像《杀戮尖塔》一样，不同事件实现不同，大部分带**多个选项、多个结果**。

- `Event` 行动 → 抽 `eventType=Event` 的事件（交互多选项）。
- `Reward` 行动 → 抽 `eventType=Reward` 的事件（即时奖励，通常单选项自动结算）。
- `Negative` 行动 → 抽 `eventType=Negative` 的事件（负面）。

`preconditions` / `weight` / `repeatable` 是**事件公共字段**，抽取时统一按它们过滤：满足前置、权重 > 0、可重复或本局未命中。用前置条件即可实现「先触发某些东西后才能随机到的事件」（不再需要 linkId）。

## TbEvent 字段

| 字段 | 说明 |
|---|---|
| id | 事件 ID |
| name / desc | 事件标题与正文 |
| eventType | 分类：`Event` / `Reward` / `Negative`（复用 `ActionBehavior`，决定被哪种行动抽到） |
| preconditions | 出现前置条件 |
| weight | 随机权重（`<=0` 不进池） |
| repeatable | 是否可重复；`false` 命中后写入 `UsedEventIds`（整局级），本局不再抽到 |

## TbEventOption 字段（按 eventId 关联）

| 字段 | 说明 |
|---|---|
| id | 选项 ID |
| eventId | 所属事件 `TbEvent.id` |
| text | 选项文本 |
| effectType | 结果效果类型（`EffectType` 枚举） |
| effectValue / effectParam | 效果参数 |

`EffectType` 枚举涵盖即时效果（`GainGold` / `LowerReq` / `GainItem` / `Gamble` / `AddDish` / `UpgradeDish`）与跟进类（`FoodBattle` / `Shop` / `GameOver` / `Victory`）。即时效果由 `EffectResolver` 结算，跟进类转成后续动作（战斗/商店/结局）。

## 选项数量约定

- **单选项**：自动结算，无需玩家点选（用于奖励/负面/即时事件）。
- **多选项**：玩家在中部卡片 UI 上 n 选一（与「行动 n 选一」共用同一套 UI），执行所选分支。

> 区分两种「选择」：行动 n 选 1 是在多个原子行动间选一个来推进；事件选项分支是选中某个事件后在其结果分支间选一个。

## 执行流程

```text
（Event/Reward/Negative 行动执行，见行动系统）
  ↓
按行动 behavior 对应的 eventType，从 TbEvent 池按 前置/权重/可重复 随机一个具体事件
  ↓
取该事件的 TbEventOption：0 个→按正文即时结算；1 个→自动结算；≥2 个→玩家分支选择
  ↓
按 effectType 结算（即时效果 / 续接战斗·商店·结局）
  ↓
不可重复事件写入 UsedEventIds
```
