# 被动道具实现审计

> 配置源：`GameConfig/Datas/item.xlsx` / `被动道具`。本页记录 2026-08-03 表结构迁移和运行时核对结果。

## 结论

- 当前生成配置包含 **80** 个被动道具。
- 每个启用 ID 都必须显式注册 `PassiveItemModel`；测试会遍历整张 `TbPassiveItem`，禁止静默落入 `NoopPassiveModel`。
- 旧存档里已经从新表删除的 ID 会被安全跳过，不折金币、不触发旧效果，再次保存时也不会留下幽灵道具。
- 被动表已删除 `activeItemHiddenOffset` 与 `goldHiddenOffset`。主动道具池只按 `baseWeight`；金币奖励不接受被动道具的常驻隐藏分修正。

## 已确认的触发与叠加规则

| 规则 | 最终语义 |
| --- | --- |
| 商店折扣与涨价 | 各道具依次相乘，最后统一向下取整，最低 1 金币。 |
| `item_perma_flat_all` / `item_perma_flat_all_plus` | 拾取瞬间只强化当时已有菜品；以后新获得的菜品不继承。 |
| “营业”范围 | 只有日常营业 `Normal` 与火热营业 `Super`；星级评鉴 `Feast` 不算。 |
| `item_score_to_one` | 进入日常/火热营业时消费一次并把目标设为 1；失败也已消费；星级评鉴不消费。 |
| `item_gold_meal_bonus` | 只在日常营业完成时发放 `+10` 并扣一次；成功、失败、终局失败都算完成。 |
| `item_gold_percent` / `item_gold_meal_penalty` | 只修正日常/火热营业的基础金币；星级评鉴和其它奖励不修改。 |
| `item_gold_on_shop` | 每次新进入商店发 `+15`；恢复同一个商店不重复。事件选项进入的商店也算一次。 |
| `item_gold_on_event` | 进入 Event/Reward/Negative 根事件页时发 `+15`；恢复同一事件页不重复。利息页与 Slot 不算事件入口。 |
| `item_extra_item_choice` | 每完成 4 次火热营业计数一次，成功或失败都计；仍存活时立即排入独立 3 选 1，被终局失败截断时只计数不发奖。 |
| `item_lucky_guarantee` | 配置值 4 表示先经历 4 次自然事件抽取，第 5 次保底 Reward；自然抽到 Reward 不重置。强制事件队列优先，已到期保底顺延。 |
| `item_more_super_actions` | 大组先做 min/max 保底候选过滤，再将含火热行动的大组权重乘以 `1 + effectValue`；已保存的行动组不重抽。 |
| `item_slot_win_chance` | 先归一化奖池，再把总中奖率乘以 `1 + effectValue`，奖励内部比例不变，空奖吃剩余概率；超过 100% 时奖励归一到 100%、空奖为 0 并告警。 |
| `item_count_as_all` | 参与全部食物数量前提和道具数量门槛，不只影响菜品技能。 |
| `item_randomize_items` | 替换出的道具不触发 `OnAcquired`，避免洗牌递归发奖或重复即时效果。 |
| `item_loan` | 只有还款节点能成功放到当前周末时才发 100 金币；无行动轴时不会白拿。 |
| `item_extra_day` / `item_extra_interest` | 按配置应用到当前及后续每周；同周幂等，玩家删除本周新增利息节点后不会自动补回。 |
| `item_gold_on_transfer` | 累计 10 次甜蜜传递只发一次 10 金币，状态随存档保存，发放后图标进入已使用态。 |

## 自动验收

- Luban 必须能从当前 Excel 完整生成 C# 与 JSON。
- `TbPassiveItem` 不允许重复 ID、空 ID 或空名称。
- 生成的 `PassiveItem.cs` / `tbpassiveitem.json` 不允许再出现 `activeItemHiddenOffset`、`goldHiddenOffset`。
- 每个配置 ID 必须有显式模型。
- 定向测试覆盖配置迁移、营业触发时机、存档去重、折扣公式、抽奖概率、行动大组权重、事件保底和隐藏分隔离。
