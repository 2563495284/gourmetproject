# 装饰品实现审计

> 配置源：`GameConfig/Datas/item.xlsx` / `装饰品`。本页记录 2026-08-04 表结构迁移和运行时核对结果。

## 结论

- 当前生成配置包含 **91** 个装饰品。
- 每个启用 ID 都必须显式注册 `PassiveItemModel`；测试会遍历整张 `TbPassiveItem`，禁止静默落入 `NoopPassiveModel`。
- 旧存档里已经从新表删除的 ID 会被安全跳过，不折金币、不触发旧效果，再次保存时也不会留下幽灵装饰品和消耗品。
- 被动表已删除 `activeItemHiddenOffset` 与 `goldHiddenOffset`。消耗品池只按 `baseWeight`；金币奖励不接受装饰品的常驻隐藏分修正。

## 已确认的触发与叠加规则

| 规则 | 最终语义 |
| --- | --- |
| 商店折扣与涨价 | 各装饰品和消耗品依次相乘，最后统一向下取整，最低 1 金币。 |
| 强化/调整折扣 | `item_discount_active*` 只作用于 Strengthen，`item_discount_adjust*` 只作用于 Adjust；同类 15% 与 25% 同时持有时累乘。 |
| 目标美味值增减 | 同档位装饰品和消耗品先把百分比相加，再一次性乘基础目标美味值并四舍五入；例如日常营业 `-20%` 与 `+20%` 同时持有时相互抵消。 |
| `item_perma_flat_all` / `item_perma_flat_all_plus` | 获得瞬间只强化当时已有食物；以后新获得的食物不继承。 |
| “营业”范围 | 只有日常营业 `Normal` 与火热营业 `Super`；星级评鉴 `Feast` 不算。 |
| `item_score_to_one` | 进入日常/火热营业时消费一次并把目标设为 1；失败也已消费；星级评鉴不消费。 |
| `item_gold_meal_bonus` | 只在日常营业完成时发放 `+10` 并扣一次；成功、失败、终局失败都算完成。 |
| `item_gold_percent` / `item_gold_meal_penalty` | 只修正日常/火热营业的基础金币；星级评鉴和其它奖励不修改。 |
| `item_gold_on_shop` | 每次新进入商店发 `+15`；恢复同一个商店不重复。事件选项进入的商店也算一次。 |
| `item_gold_on_event` | 进入 Event/Reward/Negative 根事件页时发 `+15`；恢复同一事件页不重复。利息页与 Slot 不算事件入口。 |
| 营业/评鉴失败领奖 | 本场失败但失去红心后仍有心时，照常领取本场基础奖励；心归零时只结算计数，不再发续局奖励。 |
| `item_famous_knife` | 最后一颗心即将因分数未达标而归零时消耗自身并保留 1 心；本场按失败但存活继续发基础及额外奖励。 |
| `item_heart_flat_all` | 每次结算开始读取当前红心；每颗红心使每道食物加法区增加 `effectValue`，不是永久强化。 |
| `item_empty_heart_mult_all` | 每次结算开始读取空红心；每颗空红心使每道食物倍率加区增加 `effectValue`。 |
| `item_extra_food_choice` | 每完成配置 `effectParam=every:N` 指定次数的日常营业触发；成功、失败都计，仍存活时排入独立 3 选 1，终局失败只计数不发奖。 |
| `item_extra_item_choice` | 每完成 4 次火热营业计数一次，成功或失败都计；仍存活时立即排入独立 3 选 1，被终局失败截断时只计数不发奖。 |
| `item_lucky_guarantee` | 配置值 4 表示先经历 4 次自然事件抽取，第 5 次保底 Reward；自然抽到 Reward 不重置。强制事件队列优先，已到期保底顺延。 |
| `item_more_super_actions` | 火热类别的权重与上下保底目标都乘以 `1 + effectValue`；保底目标四舍五入，`-1` 保持不限。 |
| `item_lucky_chance` | 在自然 `act_event` 合并池中，将主分类为 Reward 的事件权重乘以 `1 + effectValue`；不影响强制队列。 |
| `item_more_events` | 事件行动类别的权重与上下保底目标都乘以 `1 + effectValue`；保底目标四舍五入，`-1` 保持不限。 |
| `item_slot_win_chance` | 先归一化奖池，再把总中奖率乘以 `1 + effectValue`，奖励内部比例不变，空奖吃剩余概率；超过 100% 时奖励归一到 100%、空奖为 0 并告警。 |
| `item_count_as_all` | 参与全部食物数量前提和装饰品和消耗品数量门槛，不只影响食物技能。 |
| `item_every3_next_mult` | `every:3` 表示每上菜 3 个后强化下一个，因此命中第 4、8、12……个上菜食物；每场重新计数。 |
| `item_transfer_target_mult` | 结算阶段每实际传递到一个目标，该目标的倍率永久 `+effectValue`；默认 `+0.1`。 |
| `item_transfer_source_mult` | 结算阶段按实际目标数逐次触发；一次从 A 传给 B、C 时，A 累计 `+0.2` 倍率。 |
| `item_skill_count_mult` | 在 `AfterAllDishes` 阶段读取本次餐桌上的技能数，为所有食物增加倍率；同次结算结束后才落地的传递不会倒推本次计数。 |
| `item_randomize_items` | 替换出的装饰品和消耗品不触发 `OnAcquired`，避免洗牌递归发奖或重复即时效果。 |
| `item_copy_food` | 获得时用独立随机流从获得当刻已有食谱格中随机选择并完整克隆，包含风味、额外技能、永久分数及倍率；空食谱安全跳过。 |
| `item_timeline_random` | 获得时只打乱未来、未触发、非 星级评鉴节点之间的行动；日期、节点 ID、当前节点和已触发节点保持不变。 |
| `item_loan` | 只有还款节点能成功放到当前周末时才发 100 金币；无时间轴时不会白拿。 |
| `item_extra_day` / `item_extra_interest` | 按配置应用到当前及后续每周；同周幂等，玩家删除本周新增利息节点后不会自动补回。 |
| `item_gold_on_transfer` | 在结算阶段按每个实际传递目标累计；累计 10 次只发一次 10 金币，状态随存档保存，发放后图标进入已使用态。 |
| 丢弃次数 | 日常营业/火热营业/星级评鉴每场创建时恢复到当前最大值；局内显示剩余、局外显示最大值，战中获得或移除垃圾桶装饰会实时调整。Boss 的禁丢弃规则仍可把本场初始值覆盖为 0。 |
| 来源装饰品和消耗品被移除 | `item_gold_meal_bonus`、`item_score_to_one`、`item_cake_retain` 的剩余 buff/计数立即清零；直接移除、整体替换与旧档缺失来源都一致。已经永久写入食谱的强化及已落地的时间轴节点不回滚。 |

## 自动验收

- Luban 必须能从当前 Excel 完整生成 C# 与 JSON。
- `TbPassiveItem` 不允许重复 ID、空 ID 或空名称。
- 生成的 `PassiveItem.cs` / `tbpassiveitem.json` 不允许再出现 `activeItemHiddenOffset`、`goldHiddenOffset`。
- 每个配置 ID 必须有显式模型。
- 定向测试覆盖配置迁移、营业触发时机、存档去重、折扣公式、抽奖概率、行动类别权重/保底、事件保底和隐藏分隔离。
