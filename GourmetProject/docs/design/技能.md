# 菜品技能设计与实现规格

> 面向策划 + 程序。定义「菜品技能」的组合语法、每条前提/行为的精确语义与公式、以及它落到配置表与结算管线的方式。
>
> 对应结算基础：见 [分数结算.md](分数结算.md)。技能通过 `TbSkill` + 子表 `TbSkillRule` 配置，运行时由 `SkillRuleEffectSource` 解释后进入结算管线。

---

## 1. 一句话理解

一个技能 = **有序的若干「规则」**。每条规则 = **前提（可选）× 行为**。

- **前提（precondition）** 把当前局面折算成一个非负整数 `count`。
- **行为（action）** 以 `效果 × count` 施加到「目标作用域」的菜品（或棋盘/局面）。
- `count = 0` 时该行为不触发；无前提时 `count = 1`（行为恒定触发一次）。

一个完整技能至少要有一条**行为**。三种常见模版：

| 模版 | 规则组成 |
| --- | --- |
| 行为 | 1 条规则：前提=None + 行为 |
| 前提 + 行为 | 1 条规则：前提 + 行为 |
| 行为 + 行为 | 多条规则：各自前提 + 行为 |

## 2. 通用词表

### 2.1 作用域（Scope）

前提用它决定「在哪里数」，行为用它决定「作用到谁」。

| 作用域 | 枚举 | 含义 |
| --- | --- | --- |
| 本 | `Self` | 携带该技能的菜品本身 |
| 相邻 | `Adjacent` | 与本菜至少共一条边的其它菜 |
| 周围 | `Round` | 与本菜至少共一条边的其它菜 |
| 周围及自身 | `RoundAndSelf` | `Round` 加上携带该技能的菜品本身 |
| 同行 | `Row` | 与本菜占格同一行（Y 相同）的其它菜 |
| 本行 | `RowAndSelf` | `Row` 加上携带该技能的菜品本身 |
| 同列 | `Column` | 与本菜占格同一列（X 相同）的其它菜 |
| 本列 | `ColumnAndSelf` | `Column` 加上携带该技能的菜品本身 |
| 全部 | `All` | 棋盘上所有菜（含携带该技能的菜品本身） |
| 其他 | `Other` | 棋盘上所有其它菜（不含携带该技能的菜品本身） |
| 欢乐蛋糕效果 | `CakeBuff` | 全局欢乐蛋糕层数效果标记，不选择菜品目标 |
| 空 | `Empty` | 棋盘存在且未占用的格子（仅计数类前提用） |
| 边缘 | `Edge` | 处于棋盘存在区域包围盒边缘的格 / 菜 |
| 前面 | `Before` | 上菜顺序早于本菜的菜 |
| 后面 | `After` | 上菜顺序晚于本菜的菜 |
| 菜谱 | `Recipe` | 本次品鉴的菜谱内容（含已上、未上） |
| 分类 | `Category` | 棋盘上属于某分类（如 `cake`）的全部菜（含自身若匹配）；分类名由 `actionParam` 的 `cat:xxx` 指定 |

> 行为作用域 `Category` 还可配 `actionParam` 的 `skilltype:XXX`，进一步只作用于「带某行为类技能」的菜（如巧克力「此类食物」= 带甜蜜传递的菜）。

> 「同行/同列」以本菜任意占格所在的行/列判定：只要目标菜有一格与本菜的某一行（或列）相交即计入。

### 2.2 计数单位（Unit，种/个）

| 单位 | 枚举 | 含义 |
| --- | --- | --- |
| 个 | `Instances` | 按实例数量统计（默认） |
| 种 | `Kinds` | 按菜品本体 `BaseId` 去重后的种类数 |

### 2.3 计数模式（CountMode）

把前提的「原始数量 `raw`」折算成最终 `count`：

| 模式 | 枚举 | count |
| --- | --- | --- |
| 每有 | `Per` | `count = raw`（每有 1 个就叠一层效果） |
| 达到 | `Reach` | `count = (raw 满足 compare 阈值) ? 1 : 0`（阶梯闸门） |
| 闸门 | `Gate` | `count = (布尔条件成立) ? 1 : 0`（位置填满、边缘等） |

### 2.4 比较符（CompareOp）

`Reach` / `RecipeCount` / `DishSize` 用它比较：`None / Gte(≥) / Lte(≤) / Eq(=) / Gt(>) / Lt(<)`。

### 2.5 触发时机（Trigger）

| 时机 | 枚举 | 说明 |
| --- | --- | --- |
| 结算时 | `OnSettle` | 默认。玩家「吃」时进入结算管线执行 |
| 上菜时 | `OnServe` | 本菜被放上棋盘的瞬间执行一次（serve-time 子流程） |

## 3. 前提目录（SkillConditionType）

每项给出：作用域取值、计数方式、`raw` 的精确定义。`count` 由 §2.3 的模式折算。

| 前提 | 枚举 | 典型作用域 | raw 定义 |
| --- | --- | --- | --- |
| 无 | `None` | — | 恒为 1（无前提） |
| 位置填满 | `PositionFilled` | Row/Column/Adjacent/Round/All | 该作用域内的**存在格**是否全部被占用 → 1/0（Gate） |
| 空格 | `EmptyCell` | Adjacent/Round/Row/Column/All(=空) | 该作用域内**存在且未占用**的格数 |
| 边缘 | `Edge` | Self | 本菜是否占到棋盘存在区域包围盒的边缘 → 1/0（Gate） |
| 数量 | `DishCount` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内的菜数（按 Unit 统计） |
| 阶梯数量 | `DishCount`+`Reach` | 同上 | 同上，但用 `Reach` + `condParam` 阈值折算成闸门（如 `gte:5` 或 `tiers:5\|15\|25`） |
| 大小 | `DishSize` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内**占格数满足 `condParam` 比较条件**的菜数（如 `gte:2`、`>=2`） |
| 顺序 | `ServeOrder` | Before/After | 上菜顺序在本菜之前/之后的菜数 |
| 空间相同 | `SameDish` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内与本菜**同 BaseId** 的其它菜数（Unit=种时恒 0/1） |
| 大局相同 | `SameKindInRun` | Self | 本局（整个 GameRun）中本 BaseId **已结算过的次数** |
| 小局相同 | `SameKindInMeal` | Self/All | 本次品鉴中本 BaseId 的数量（Unit=个：棋盘现存同种数；`condParam="settled"`：本次品鉴已结算过的同种次数） |
| 标签 | `TagCount` | Self | 本菜携带的标签数（技能数 + 有风味则 +1；Unit=种时按不同效果去重） |
| 技能数 | `SkillCount` | Self | 本菜技能数（基础技能 + 甜蜜传递过来的外来子技能） |
| 形状 | `ShapeMatch` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内占格形状匹配 `condParam`（如 `1x1`）的菜数 |
| 上菜时 | `DishCount`+`Trigger=OnServe` | Row/Column/Adjacent/Round/All | 与「数量」相同，但在上菜瞬间求值 |
| 菜谱 | `RecipeCount` | Recipe | 菜谱内菜品数（按 Unit）**compare 阈值** → 1/0（Gate） |
| 层数 | `LayerCount` | Self | 当前**全局欢乐蛋糕层数**（见 §5.1）；`condParam="cap:N"` 时封顶为 `min(层数, N)` |
| 分类数量 | `CategoryCount` | — | 棋盘上分类 = `condParam`（如 `cake`）的菜数（按 Unit）；可与 `tiers:` 合写（如 `cake;tiers:3\|5\|8`） |
| 行为类数量 | `SkillTypeCount` | — | 棋盘上「带某行为类技能」的菜数（按 Unit）；行为类名取 `condParam`（如 `TransferSkills`），可与 `tiers:` 合写 |
| 占格数 | `OccupiedCell` | Self | 本菜当前占用格数 |

> 说明：
> - `PositionFilled` 的 All 作用域指整个棋盘被填满。
> - 是否包含本菜由作用域枚举决定：`Round/Row/Column` 不含自身，`RoundAndSelf/RowAndSelf/ColumnAndSelf` 含自身，`All` 表示全场所有菜并含自身；`Adjacent` 天然只表示相邻其它菜。
> - 计数类前提统计「个」时按每道菜的**视为食物数 EffectiveCountAs**累加（默认 1，见 §5.4），而非恒 1。
> - 「阶梯数量」「上菜时」不是独立枚举，而是「数量」配不同 `CountMode`/`Trigger` 的写法，减少枚举爆炸。
> - **阶梯（tiers）**：`condParam` 含 `tiers:t1|t2|t3`（升序阈值）时，前提返回满足的**最高档序号**（1-based，均不满足为 0）；行为侧从 `actionParam` 的 `tiervals:v1|v2|v3` 取对应档值并只触发一次（见 §4）。

## 4. 行为目录（SkillActionType）

行为的效果值来自 `actionValue`（`list,float`）、`actionParam`（`list,string`）。作用对象由 `actionScope` 决定；`actionCount>0` 时在作用域内**随机取 N 个**（否则全部）。所有效果都会 **× 前提 count**。

| 行为 | 枚举 | 语义 | 依赖系统 |
| --- | --- | --- | --- |
| 分数增加(加) | `AddFlat` | 目标菜加法区 `+= actionValue[0] × count` | 现有管线 |
| 分数增加(乘) | `AddMult` | 默认目标菜乘区 `×= actionValue[0]`（每 count 叠乘一次，即 `pow(v, count)`）；`actionParam=linear` 时改为 `×= 1 + actionValue[0] × count` | 现有管线 |
| 倍率增加(加) | `AddMultFlat` | 目标菜乘区**线性 +**`actionValue[0] × count`（区别于 `AddMult` 的幂叠；即「倍率 +X」） | 现有管线 |
| 当前倍率增加(加) | `AddCurrentMult` | 目标菜乘区加上来源食物结算到当前时刻的倍率之和；默认来源为技能运行时自身，`actionParam=source:one-cell` 时来源为全场所有实际占 1 格食物。先统一读取来源快照，再写入所有目标 | 跨菜倍率读取 |
| 当前分数增加(加) | `AddCurrentScore` | 目标菜加法区加上来源食物结算到当前时刻的分数（基础分 + 固定加分，不含倍率）；来源为技能运行时自身。先读取快照，再写入所有目标 | 跨菜分数读取 |
| 分数传递 | `TransferScore` | 把来源菜当前贡献的 `actionValue[0]`（比例，如 1/3）转移加到目标菜 | 现有管线（跨菜命令） |
| 技能额外触发 | `ExtraSettlement` | 目标菜技能额外触发 `actionValue[0]` 次；额外触发只重跑目标的 `DishSkills` 条目，且跳过 `ExtraSettlement` 自身以避免递归 | 跨菜命令 + 技能阶段重入 |
| 永久加分 | `PermanentAddFlat` | 目标菜**永久加法分** `+= actionValue[0] × count`：本次结算即计入，并持久到实例（本次品鉴内每次结算叠加进基础分，见 §5.3） | 永久系统(§5.3) |
| 永久乘区 | `PermanentAddMult` | 目标菜**永久乘区** `×= actionValue[0]`：本次结算即计入，并持久到实例（本次品鉴内每次结算叠乘进乘区初值） | 永久系统(§5.3) |
| 视为食物数 | `AddCountAs` | 目标菜「视为食物数」`+= round(actionValue[0] × count)`；**当次结算 live 生效**（见 §5.4） | 视为食物数(§5.4) |
| 层数增加 | `AddLayer` | **全局欢乐蛋糕层数** `+actionValue[0] × count`；`actionParam` 以 `mult` 开头时改为 `×actionValue[0]`（可写 `multfloor:N` 保证至少净 +N） | 全局层数(§5.1) |
| 层数消耗 | `ConsumeLayer` | **全局欢乐蛋糕层数** `-actionValue[0] × count`（下限 0） | 全局层数(§5.1) |
| 甜蜜传递 | `TransferSkills` | 把**本子技能所在 skill 内的其他子技能**（即同一菜品技能里除传递外的效果）作为「外来子技能」传给作用域内**有食物的格子**；`OnServe` 时在候选中**均权随机**取 `actionCount` 个（0=全部），接收方把这些外来子技能挂到自身、并在本次美食结算时随自身一并施加（作用域相对接收方计算），记录来源标签「源菜名<甜蜜传递>」用于明细/tips 展示（见 §5.2） | 外来子技能(§5.2)+上菜/结算前置 |
| 代触发甜蜜传递 | `TriggerSweetTransfer` | 扫描作用域内带 `TransferSkills` 的食物，并让它们各执行一次甜蜜传递。这不会重跑来源的整个技能，只执行其 `TransferSkills` 子技能，把同一 skill 内其他可传递子技能交给目标。枫糖使用 `actionScope=All, actionCount=1` 随机选 1 个来源；大棒棒糖使用 `actionParam=axis:rowcol;skilltype:TransferSkills` 选取同行同列全部来源。传递载荷、候选目标和目标数沿用来源的 `TransferSkills` 子技能 | 外来子技能(§5.2)+上菜/结算前置 |
| 技能复制 | `CopySkill` | 从候选池随机取 `actionValue[0]` 个技能加到目标（默认本菜）；候选池 = `actionParam` 含 `cat:xxx` 时该分类全部菜品定义的技能，否则作用域内其它实例的技能（剔除自身已有与复制类）；需 RNG，OnServe 落地(§5.5) | 技能复制(§5.5) |
| 临时复制 | `TempCopyDish` | 把本菜临时克隆到一个空格（同技能/风味，标记临时）；品鉴结束清理，临时克隆不再触发临时复制；需 RNG，OnServe 落地(§5.5) | 临时复制(§5.5) |
| 经济运营 | `GrantGold` | 获得 `actionValue[0] × count` 金币 | 金币桥接(§6) |

> - `AddFlat`/`AddMult` 在 `actionScope=Self` 时就是最常见的「本菜加分/乘分」，等价旧 `FlavorEffectType.AddFlat/AddMult`。
> - **阶梯行为**：当规则前提为阶梯（`tiers:`）时，`count` 是满足档序号，行为改用 `actionParam` 的 `tiervals:` 对应档值并只触发一次（不再 × count）。
> - `CopySkill`/`TempCopyDish` 需要随机流，结算/上菜阶段只登记请求，由 `BattleSession` 用注入的 `IRandomStream` 落地。

## 5. 新增运行时概念

### 5.1 全局欢乐蛋糕层数

- **归属**：整场品鉴（一个 `BattleSession`）共享**一个**全局计数器 `HappyCakeLayers`（默认 0），跨品鉴重置。不再是每菜各自的层数。
- **读写**：
  - `AddLayer`/`ConsumeLayer` 行为改写全局计数器（无论作用域，统一改一次）；上菜（`OnServe`）阶段由 `ServeRuleResolver` 即时累加，结算（`OnSettle`）阶段以 `ScoreResult.HappyCakeLayerDelta` 增量形式返回，由 `BattleSession` 写回。
  - `LayerCount` 前提读取「本次品鉴开始层数 + 已产生增量」；`condParam="cap:N"` 时封顶 `min(层数, N)`（层数封顶机制，供设计复用）。
- **乘法层**：`AddLayer` 的 `actionParam` 以 `mult` 开头时按 `×值` 结算；`multfloor:N` 额外保证至少净 +N（如舒芙蕾「×1.5 层，至少 +5 层」）。
- **典型链路**：泡芙/奶油小格上菜积层 → 舒芙蕾放大 → 闪电泡芙 `ConsumeLayer` 消耗 10 层欢乐蛋糕。闪电泡芙的「消耗 10 层」与「倍率 +5」是**两条相互独立的子技能**：即使当前层数不足 10（消耗后封顶到 0），倍率 +5 仍照常触发，二者无门槛依赖。

### 5.2 运行时技能集 / 外来子技能

- `DishInstance` 除只读 `Def.SkillIds` 外，持有运行时可变技能集 `SkillIds`（初始 = 合成后的技能）；`CopySkill` 向其追加技能 id（去重）。
- **外来子技能（甜蜜传递）**：`DishInstance` 另持有 `TransferredSkills`（`SkillEffect`(规则+描述) + 来源标签的列表）。甜蜜传递传的**不是整菜技能 id**，而是「传递子技能所在 skill 内的其他子技能(rule)」——因为已做「一菜一 skill」，同菜的计分/被动子技能与传递子技能同处一个 skill。
- **一菜一 skill**：每道菜的 `dish_base.skills` 只引用一个技能，甜蜜传递作为该技能的一个子技能。这样传递 = 把本菜的其他子技能给别人，语义自洽；传递子技能本身被 `EffectsToTransfer` 排除，不会链式传递。
- **甜蜜传递落地（OnServe）**：`ServeRuleResolver` 只收集 `SkillTransferRequest`（源实例 Id、源菜名、候选目标 Id 列表=作用域内有食物且非自身的菜、**外来子技能 `Effects`**、`actionCount`），由 `BattleSession` 用注入的 `IRandomStream` 在候选中**均权随机**取 `count` 个（0=全部）落地，把 `Effects` 追加到目标 `TransferredSkills`。临时克隆会复制外来子技能与来源标签。
- **代触发甜蜜传递（枫糖/大棒棒糖）**：`TriggerSweetTransfer` 不重跑来源的整个技能，也不触发其他子技能；只代执行来源的 `TransferSkills` 子技能，把同一 skill 内其他可传递子技能交给目标。枫糖随机选 1 个来源，大棒棒糖处理同行同列全部来源；来源标签、传递载荷、目标作用域和 `actionCount` 都来自被触发食物自身。
- **结算与生效时机**：外来子技能随本次美食（一个 `BattleSession`）内的结算一并施加（`SkillRuleEffectSource` 除遍历自身技能外，也遍历 `TransferredSkills` 的 `OnSettle` 规则，作用域相对接收方计算）；一次美食只结算一次，即「传递后对目标生效一次」，美食结束实例销毁即清除，不跨美食保留。
- **技能来源溯源**：外来子技能带来源标签「源菜名<甜蜜传递>」，结算明细用 `ScoreSource.TransferredDishSkill` 以来源标签命名该行；菜品详情/tips 单独列出每条外来子技能（`【源名<甜蜜传递>】子技能描述`）。运行时技能集里由 `CopySkill` 获得的技能仍用 `skillId → 来源标签` 映射（`GetSkillSource`）。

### 5.3 永久加分 / 永久乘区

- `DishInstance` 持有 `PermanentFlatBonus`（默认 0）与 `PermanentMultBonus`（默认 1）。
- `PermanentAddFlat`/`PermanentAddMult` 行为：**本次结算即生效**（当次直接进加法区/乘区），同时把增量登记到 `ScoreResult`，由 `BattleSession` 结算后写回实例。
- 写回后，`PermanentFlatBonus` 计入下次结算的**基础分**、`PermanentMultBonus` 计入下次结算的**乘区初值**，故本次品鉴内多次结算会持续累积（如巧克力糖「每有 1 技能永久 +5」、太妃糖「分数永久 +10」并把该永久加分甜蜜传递给 2 个食物）。
- **作用范围**：`DishInstance` 每场品鉴重建，永久加成**仅在本场品鉴内**累积，不跨品鉴/整局持久（棋盘状态不随存档保存）。

### 5.4 视为食物数（EffectiveCountAs）

- 每道菜有静态「视为食物数」`Def.CountAs`（默认 1，`dish_base.countAs`），计数类前提统计「个」时按此累加（如圣代视为 2、芭菲视为 10）。
- `AddCountAs` 行为可动态改写：由 `ScoreContext` 在**结算前 live 预计算**（`ComputeLiveCountAs`），按当前局面把「本菜条件视为 N」（如华夫饼「同行填满视为 10」）与「对作用域菜 +N」（如铜锣烧「同列 +2」）当次生效，不做跨结算持久（避免单次结算模型下永不触发）。
- 计算 live 值时其条件用非 live 计数评估，避免「视为」递归依赖「视为」。

### 5.5 技能复制 / 临时复制（RNG 副作用）

- `CopySkill`/`TempCopyDish` 需要随机流，故结算/上菜阶段只**登记请求**（候选技能池 / 待克隆源实例），由 `BattleSession` 用注入的 `IRandomStream` 落地。
- 复制：从候选池随机取 N 个不同技能 `AddSkill` 到目标（杯子蛋糕/月饼取周围技能、双层蛋糕从 `cat:cake` 技能池取 3 个）。
- 临时复制：在空格中克隆源实例（同技能/风味），标记 `IsTemporary`；`BattleSession.ClearTemporaryDishes` 在品鉴结束清理，临时克隆自身不再触发临时复制。
- 二者均为 `OnServe`，使复制/克隆得到的技能能参与本场结算。

### 5.6 品鉴 / 整局历史

- **小局（本次美食品鉴 = 一场战斗 `BattleSession`）**：记录本场已结算过的菜品 BaseId 计数 `MealSettledCount[baseId]`。
- **大局（整局 `GameRun`）**：记录整局累计已结算过的菜品 BaseId 计数 `RunSettledCount[baseId]`，随存档保存。
- 结算完成（`Settle`）时把本场各菜 BaseId 累加进上述两个计数；这两个计数以**只读快照**注入结算，供 `SameKindInMeal`/`SameKindInRun` 读取（读取的是**本次结算之前**的历史，避免自累加）。

## 6. 金币桥接（经济运营）

结算层是纯 C#，不能引用 `GameRun`。`GrantGold` 不直接改金币，而是：

1. 行为把金币增量写进 `ScoreContext` 的侧效果累加器。
2. `ScoreResult` 暴露 `GoldDelta`（及未来其它侧效果）。
3. `BattleSession.Settle` 汇总；Game 层在结算演出完成后把 `GoldDelta` 写回 `GameRun.Gold`。

预览分（`PreviewScore`）也会算出 `GoldDelta`，但**不入账**（只有正式 `Settle` 才由 Game 层应用）。

## 7. 配置落地（TbSkill + TbSkillRule）

### 7.1 主表 `TbSkill`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 技能ID（主键） |
| name | string | 技能名称 |
| desc | string | 描述（直接写可展示文本） |
| termId | string | 关联术语ID（可空） |

> 菜品技能效果统一由子表 `TbSkillRule` 表达；`TbSkill` 只保存展示与术语元信息。

### 7.2 子表 `TbSkillRule`（`skill_rule@dish.xlsx`）

一行 = 一条规则，同 `skillId` 多行按 `order` 升序执行。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 规则ID（主键） |
| skillId | string | 所属技能 → `TbSkill.id` |
| order | int | 同技能内执行顺序 |
| trigger | SkillTrigger | 触发时机（OnSettle/OnServe） |
| condType | SkillConditionType | 前提类型（None=无前提） |
| condScope | SkillScope | 前提作用域；`Other` 表示全部但不含自身，`CakeBuff` 表示全局欢乐蛋糕层数效果 |
| condUnit | CountUnit | 计数单位（个/种） |
| condMode | CountMode | 计数模式（Per/Reach/Gate） |
| condParam | string | 前提附加参数（如形状 `1x1`、`settled`、比较阈值 `gte:2`/`>=2`、阶梯 `tiers:5\|15\|25`） |
| actionType | SkillActionType | 行为类型 |
| actionScope | SkillScope | 行为作用域（目标）；`CakeBuff` 用于 `AddLayer` 等全局欢乐蛋糕层数效果，不选择菜品目标 |
| actionCount | int | 随机目标数（0=全部） |
| actionValue | list,float | 行为数值 |
| actionParam | list,string | 行为参数（如 `mult`、`keep_transfer`） |

## 8. 结算接入

- `SkillRuleEffectSource : IScoreEffectSource` 遍历每道菜的运行时技能 → 技能规则 → 求前提 `count` → 产出行为效果条目。
- 前提求值器（`SkillConditionEvaluator`）按 `condType/condScope/...` 用 `Board`、只读历史、菜谱快照算 `raw` 再折算 `count`。
- 行为通过 `ScoreContext` 命令改分（`AddFlat/MultiplyBy`、目标菜命令、`TransferScore`、`ExtraSettlement`、`GrantGold`、层数命令），受 `MaxCommandsPerCalculation` 安全阀保护。
- 默认阶段：OnSettle 规则在 `DishSkills` 阶段；跨菜/局级行为可提升到 `AfterAllDishes`/`Final`（由 source 决定 `Phase`）。
- OnServe 规则在 `BattleSession.Serve` 后由一个轻量 serve-time 结算子流程执行（仅处理该实例的 OnServe 规则）。

---

## 9. 红线

- 结算层保持纯 C#、不引用 Unity/`GameRun`；金币等外部副作用只经 `ScoreResult` 侧效果桥接。
- 不在结算器里写具体技能硬编码分支：新前提/新行为走「枚举 + 求值器/派发器」扩展。
- 顺序依赖用 `order` 与 `Priority` 表达，不依赖隐性行顺序。
- 每新增前提/行为都要补 EditMode 测试（count 计算 / 行为效果 / 组合 / 明细来源）。
