# 食物技能设计与实现规格

> 面向策划 + 程序。定义「食物技能」的组合语法、每条前提/行为的精确语义与公式、以及它落到配置表与结算管线的方式。
>
> 对应结算基础：见 [美味值结算.md](美味值结算.md)。技能通过 `TbSkill` + 子表 `TbSubSkill` 配置，运行时由 `SkillRuleEffectSource` 解释后进入结算管线。

---

## 1. 一句话理解

一个技能 = **有序的若干「规则」**。每条规则 = **前提（可选）× 行为**。

- **前提（precondition）** 把当前局面折算成一个非负整数 `count`。
- **行为（action）** 以 `效果 × count` 施加到「目标作用域」的食物（或棋盘/局面）。
- `count = 0` 时该行为不触发；无前提时 `count = 1`（行为恒定触发一次）。

一个完整技能至少要有一条**行为**。三种常见模版：

| 模版 | 规则组成 |
| --- | --- |
| 行为 | 1 条规则：前提=None + 行为 |
| 前提 + 行为 | 1 条规则：前提 + 行为 |
| 行为 + 行为 | 多条规则：各自前提 + 行为 |

## 2. 通用词表

### 2.1 作用域（Scope）

前提用它决定「在哪里数」，行为用它决定「作用到谁」。

| 作用域 | 枚举 | 含义 |
| --- | --- | --- |
| 本 | `Self` | 携带该技能的食物本身 |
| 相邻 | `Adjacent` | 与本菜至少共一条边的其它菜 |
| 周围 | `Round` | 与本菜至少共一条边的其它菜 |
| 周围及自身 | `RoundAndSelf` | `Round` 加上携带该技能的食物本身 |
| 同行 | `Row` | 与本菜占格同一行（Y 相同）的其它菜 |
| 本行 | `RowAndSelf` | `Row` 加上携带该技能的食物本身 |
| 同列 | `Column` | 与本菜占格同一列（X 相同）的其它菜 |
| 本列 | `ColumnAndSelf` | `Column` 加上携带该技能的食物本身 |
| 同行同列 | `RowAndColumn` | `Row` 与 `Column` 的并集，不含携带该技能的食物本身 |
| 左侧 | `Left` | 逐行取本菜每个占用行中，最左占格左边的存在格 / 菜 |
| 上侧 | `Up` | 逐列取本菜每个占用列中，最上占格上边的存在格 / 菜 |
| 右侧 | `Right` | 逐行取本菜每个占用行中，最右占格右边的存在格 / 菜 |
| 下侧 | `Down` | 逐列取本菜每个占用列中，最下占格下边的存在格 / 菜 |
| 全部 | `All` | 棋盘上所有食物（含携带该技能的食物本身） |
| 其他 | `Other` | 棋盘上所有其它菜（不含携带该技能的食物本身） |
| 欢乐蛋糕效果 | `CakeBuff` | 全局欢乐蛋糕层数效果标记，不选择食物目标 |
| 空 | `Empty` | 棋盘存在且未占用的格子（仅计数类前提用） |
| 边缘 | `Edge` | 处于棋盘存在区域包围盒边缘的格 / 菜 |
| 前面 | `Before` | 上菜顺序早于本食物的菜 |
| 后面 | `After` | 上菜顺序晚于本食物的菜 |
| 食谱 | `Recipe` | 本场经营挑战的食谱内容（含已上、未上） |
| 分类 | `Category` | 棋盘上属于某分类（如 `cake`）的全部菜（含自身若匹配）；分类名由 `actionParam` 的 `cat:xxx` 指定 |

> 行为作用域 `Category` 还可配 `actionParam` 的 `skilltype:XXX`，进一步只作用于「带某行为类技能」的菜（如巧克力「此类食物」= 带甜蜜传递的菜）。任意空间作用域也可配 `cat:xxx` / `skilltype:XXX` 做联合筛选；方向作用域可配 `include:self` 把自身加入结果。

> 「同行/同列」以本菜任意占格所在的行/列判定：只要目标食物有一格与本食物的某一行（或列）相交即计入。

> 「左/上/右/下侧」按本食物的实际多格形状逐行或逐列投影到棋盘边界，仅保留棋盘存在格，不包含本菜自身。凹形食物可能让同一格同时属于两个方向（例如左侧与上侧）。

### 2.2 计数单位（Unit，份/个/种）

| 单位 | 枚举 | 含义 |
| --- | --- | --- |
| 份 | `Instances` | 按当前有效份数统计（默认），包含食物静态份数及本次结算内的额外份数 |
| 种 | `Kinds` | 按食物本体 `BaseId` 去重后的种类数 |
| 个 | `PhysicalInstances` | 按实际食物数量统计，不受“视为份数”影响 |

### 2.3 计数模式（CountMode）

把前提的「原始数量 `raw`」折算成最终 `count`：

| 模式 | 枚举 | count |
| --- | --- | --- |
| 每有 | `Per` | `count = raw`（每有 1 个就叠一层效果） |
| 达到 | `Reach` | `count = (raw 满足 compare 阈值) ? 1 : 0`（阶梯闸门） |
| 闸门 | `Gate` | `count = (布尔条件成立) ? 1 : 0`（位置填满、边缘等） |

### 2.4 比较符（CompareOp）

`Reach` / `RecipeCount` / `DishSize` 用它比较：`None / Gte(≥) / Lte(≤) / Eq(=) / Gt(>) / Lt(<)`。

### 2.5 触发时机（Trigger）

| 时机 | 枚举 | 说明 |
| --- | --- | --- |
| 结算时 | `OnSettle` | 默认。玩家「吃」时进入结算管线执行 |
| 上菜时 | `OnServe` | 本菜被放上棋盘的瞬间执行一次（serve-time 子流程） |

> 当前 `dish.xlsx` 中全部食物子技能均配置为 `OnSettle`；`OnServe` 仅作为框架预留能力，目前没有食物使用。

## 3. 前提目录（SkillConditionType）

每项给出：作用域取值、计数方式、`raw` 的精确定义。`count` 由 §2.3 的模式折算。

| 前提 | 枚举 | 典型作用域 | raw 定义 |
| --- | --- | --- | --- |
| 无 | `None` | — | 恒为 1（无前提） |
| 位置填满 | `PositionFilled` | Row/Column/Adjacent/Round/All | 该作用域内的**存在格**是否全部被占用 → 1/0（Gate） |
| 空格 | `EmptyCell` | Adjacent/Round/Row/Column/All(=空) | 该作用域内**存在且未占用**的格数 |
| 边缘 | `Edge` | Self | 本菜是否占到棋盘存在区域包围盒的边缘 → 1/0（Gate） |
| 数量 | `DishCount` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内的菜数（按 Unit 统计） |
| 阶梯数量 | `DishCount`+`Reach` | 同上 | 同上，但用 `Reach` + `condParam` 阈值折算成闸门（如 `gte:5` 或 `tiers:5\|15\|25`） |
| 大小 | `DishSize` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内**占格数满足 `condParam` 比较条件**的菜数（如 `gte:2`、`>=2`） |
| 顺序 | `ServeOrder` | Before/After | 上菜顺序在本菜之前/之后的菜数 |
| 空间相同 | `SameDish` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内与本菜**同 BaseId** 的其它菜数（Unit=种时恒 0/1） |
| 大局相同 | `SameKindInRun` | Self | 本局（整个 GameRun）中本 BaseId **已结算过的次数** |
| 小局相同 | `SameKindInMeal` | Self/All | 本场经营挑战中本 BaseId 的数量（Unit=个：棋盘现存同种数；`condParam="settled"`：本场经营挑战已结算过的同种次数） |
| 标签 | `TagCount` | Self | 本菜携带的标签数（技能数 + 有风味则 +1；Unit=种时按不同效果去重） |
| 技能数 | `SkillCount` | Self/Adjacent/Round/Row/Column/All 等 | 作用域内每个食物的技能数之和（基础技能 + 甜蜜传递过来的外来子技能） |
| 形状 | `ShapeMatch` | Adjacent/Round/RoundAndSelf/Row/RowAndSelf/Column/ColumnAndSelf/All | 该作用域内占格形状匹配 `condParam`（如 `1x1`）的菜数 |
| 上菜时 | `DishCount`+`Trigger=OnServe` | Row/Column/Adjacent/Round/All | 与「数量」相同，但在上菜瞬间求值 |
| 食谱 | `RecipeCount` | Recipe | 食谱内食物数（按 Unit）**compare 阈值** → 1/0（Gate） |
| 层数 | `LayerCount` | Self | 当前**全局欢乐蛋糕层数**（见 §5.1）；`condParam="cap:N"` 时封顶为 `min(层数, N)` |
| 分类数量 | `CategoryCount` | — | 棋盘上分类 = `condParam`（如 `cake`）的菜数（按 Unit）；可与 `tiers:` 合写（如 `cake;tiers:3\|5\|8`） |
| 行为类数量 | `SkillTypeCount` | Self/Adjacent/Round/Row/Column/All 等 | 作用域内「带某行为类技能」的菜数（按 Unit）；行为类名取 `condParam`（如 `TransferSkills`，也可写 `skilltype:TransferSkills`），可与 `tiers:` 合写 |
| 占格数 | `OccupiedCell` | Self | 默认读取本菜当前占用格数；`condParam=source:board` 时读取棋盘实际存在格总数 |

> 说明：
> - `PositionFilled` 的 All 作用域指整个棋盘被填满。
> - 是否包含本菜由作用域枚举决定：`Round/Row/Column/RowAndColumn` 不含自身，`RoundAndSelf/RowAndSelf/ColumnAndSelf` 含自身，`All` 表示全场所有食物并含自身；`Adjacent` 天然只表示相邻其它菜。
> - 计数类前提使用 `Instances` 时按每个食物的**有效份数 EffectiveCountAs**累加（默认 1，见 §5.4）；确实统计物理食物数量时改用 `PhysicalInstances`。
> - 「阶梯数量」「上菜时」不是独立枚举，而是「数量」配不同 `CountMode`/`Trigger` 的写法，减少枚举爆炸。
> - **阶梯（tiers）**：`condParam` 含 `tiers:t1|t2|t3`（升序阈值）时，前提返回满足的**最高档序号**（1-based，均不满足为 0）；行为侧从 `actionParam` 的 `tiervals:v1|v2|v3` 取对应档值并只触发一次（见 §4）。
> - **每 N 个折算**：`condParam` 含 `div:N` 时，先汇总完整作用域的原始数量，再执行 `floor(raw / N)`；例如 `include:self;div:2` 表示“该方向及自身每有 2 个”。

## 4. 行为目录（SkillActionType）

行为的效果值来自 `actionValue`（`list,float`）、`actionParam`（`list,string`）。作用对象由 `actionScope` 决定；`actionCount>0` 时默认按棋盘顺序取前 N 个，配置 `actionParam=target:random` 时改为在作用域内按食物实例均权、无放回随机取 N 个（否则全部）。所有效果都会 **× 前提 count**。

| 行为 | 枚举 | 语义 | 依赖系统 |
| --- | --- | --- | --- |
| 分数增加(加) | `AddFlat` | 目标食物加法区 `+= actionValue[0] × count` | 现有管线 |
| 分数增加(乘) | `AddMult` | 默认目标食物倍率 `×= actionValue[0]`（每 count 叠乘一次，即 `pow(v, count)`）；`actionParam=linear` 时改为 `×= 1 + actionValue[0] × count` | 现有管线 |
| 倍率增加(加) | `AddMultFlat` | 目标食物倍率**线性 +**`actionValue[0] × count`（区别于 `AddMult` 的幂叠；即「倍率 +X」） | 现有管线 |
| 当前倍率增加(加) | `AddCurrentMult` | 目标食物倍率加上来源食物结算到当前时刻的倍率之和；默认来源为技能运行时自身，`actionParam=source:one-cell` 时来源为全场所有实际占 1 格食物。先统一读取来源快照，再写入所有目标 | 跨菜倍率读取 |
| 当前分数增加(加) | `AddCurrentScore` | 目标食物加法区加上来源食物结算到当前时刻的分数（基础分 + 固定加分，不含倍率）；来源为技能运行时自身。先读取快照，再写入所有目标 | 跨菜分数读取 |
| 永久加分 | `PermanentAddFlat` | 目标食物**永久加法分** `+= actionValue[0] × count`：本次结算即计入，并持久到实例（本场经营挑战内每次结算叠加进基础分，见 §5.3） | 永久系统(§5.3) |
| 增加有效份数 | `AddCountAs` | 目标食物有效份数 `+= round(actionValue[0] × count)`；`actionParam=target:occupiedcells;offset:-1` 时，每个目标按“实际占格数−1”增加；**当次结算 live 生效**（见 §5.4） | 有效份数(§5.4) |
| 层数增加 | `AddLayer` | **全局欢乐蛋糕层数** `+actionValue[0] × count`；`actionParam` 以 `mult` 开头时改为 `×actionValue[0]`（可写 `multfloor:N` 保证至少净 +N） | 全局层数(§5.1) |
| 层数消耗 | `ConsumeLayer` | **全局欢乐蛋糕层数** `-actionValue[0] × count`（下限 0） | 全局层数(§5.1) |
| 甜蜜传递 | `TransferSkills` | 把**本子技能所在 skill 内的其他子技能**（即同一食物技能里除传递和传递修饰器外的效果）作为「外来子技能」，从**全场其它食物**中按权重无放回选择 `actionCount` 个接收者（0=全部）：`archetypeWeights[0]=0` 的食物权重固定为 1，`archetypeWeights[0]>0` 的甜蜜传递流派食物权重等于其 `Shape.CellCount`。接收方先获得本次子技能，再立即结算其当时已获得的**所有** `OnSettle` 甜蜜传递子技能；同一轮多次接收时，每次都会重结算包含本次新增在内的完整累计列表。正式结算后只把本次载荷写入运行时技能集一次，并记录来源标签「来源食物名<甜蜜传递>」用于明细/tips 展示。传递候选不继承同 skill 第一个子技能的作用域；候选为空、选择器返回空或非法目标时仍记录一次失败表现，但不触发任何甜蜜 Buff（见 §5.2） | 外来子技能(§5.2)+结算前置 |
| 代触发甜蜜传递 | `TriggerSweetTransfer` | 扫描作用域内带 `TransferSkills` 的食物，并让它们各执行一次甜蜜传递。这不会重跑来源的整个技能，只执行其 `TransferSkills` 子技能，把同一 skill 内其他可传递子技能交给目标。当前枫糖使用 `actionScope=All, actionCount=3` 随机选 3 个来源；大棒棒糖使用 `actionScope=RowAndColumn, actionParam=skilltype:TransferSkills` 选取同行同列全部来源。每个来源独立解析载荷、候选和目标，来源标签使用真实食物名称；单个来源失败不阻断后续来源。`actionParam=modifier:add-targets` 时该规则改为在自身结算时给作用域目标登记单次结算 Buff，而非全桌被动扫描 | 外来子技能(§5.2)+结算前置 |
| 技能复制 | `CopySkill` | 从候选池随机取 `actionValue[0]` 个技能加到目标（默认本菜）；候选池 = `actionParam` 含 `cat:xxx` 时该分类全部食物定义的技能，否则作用域内其它实例的技能（剔除自身已有与复制类）。`OnSettle` 时所选技能当次立即执行，正式结算后写回实例（见 §5.5） | 技能复制(§5.5) |
| 经济运营 | `GrantGold` | 获得 `actionValue[0] × count` 金币 | 金币桥接(§6) |

> - `AddFlat`/`AddMult` 在 `actionScope=Self` 时就是最常见的「本菜加分/乘分」，等价旧 `FlavorEffectType.AddFlat/AddMult`。
> - **阶梯行为**：当规则前提为阶梯（`tiers:`）时，`count` 是满足档序号，行为改用 `actionParam` 的 `tiervals:` 对应档值并只触发一次（不再 × count）。
> - **甜蜜传递 Buff**：`AddMult` / `AddMultFlat` 配 `actionParam=when:transfer`，或 `TriggerSweetTransfer` 配 `modifier:add-targets` 时，在规则自身轮到结算时才把 Buff 登记到 `actionScope` 内的具体食物；登记前已经发生的传递不受影响。`resultscope:BuffTargets` 表示响应结果施加给该 Buff 登记时圈定的全部食物；`scale:transfer-target-count` 表示再按本次最终去重、过滤非法 ID 后的实际接收者数量缩放，未配置时仍按一次成功发动计算一次。额外目标修饰器可配 `chance:0.6`：每次甜蜜传递发动时，每个概率修饰器各独立判定一次，成功则增加 `actionValue` 个目标；原目标数以及棉花糖、装饰品等固定额外目标数不会增加判定次数。多个概率修饰器的成功结果累加，最终仍受合法候选数封顶。预览未注入随机流时不计算概率收益。
> - `CopySkill` 需要随机流。预览使用结算快照提供的确定性选择器，不消耗正式随机流；正式结算后由 `BattleSession` 把同一选择结果写回实例。
> - **随机行为目标**：`actionParam=target:random` 使用正式结算的会话随机流；预览稳定取棋盘顺序候选，不消耗正式随机流。多格食物只算一个候选，中间有空格不影响方向作用域。

## 5. 新增运行时概念

### 5.1 全局欢乐蛋糕层数

- **归属**：整场经营挑战（一个 `BattleSession`）共享**一个**全局计数器 `HappyCakeLayers`（默认 0），跨经营挑战重置。不再是每菜各自的层数。
- **读写**：
  - `AddLayer`/`ConsumeLayer` 行为改写全局计数器（无论作用域，统一改一次）；上菜（`OnServe`）阶段由 `ServeRuleResolver` 即时累加，结算（`OnSettle`）阶段以 `ScoreResult.HappyCakeLayerDelta` 增量形式返回，由 `BattleSession` 写回。
  - `LayerCount` 前提读取「本场经营挑战开始层数 + 已产生增量」；`condParam="cap:N"` 时封顶 `min(层数, N)`（层数封顶机制，供设计复用）。
- **乘法层**：`AddLayer` 的 `actionParam` 以 `mult` 开头时按 `×值` 结算；`multfloor:N` 额外保证至少净 +N。
- **典型链路**：泡芙/奶油小格上菜积层 → 欢乐蛋糕层数放大技能 → 闪电泡芙 `ConsumeLayer` 消耗 10 层欢乐蛋糕。闪电泡芙的「消耗 10 层」与「倍率 +5」是**两条相互独立的子技能**：即使当前层数不足 10（消耗后封顶到 0），倍率 +5 仍照常触发，二者无门槛依赖。

### 5.2 运行时技能集 / 外来子技能

- `DishInstance` 除只读 `Def.SkillIds` 外，持有运行时可变技能集 `SkillIds`（初始 = 合成后的技能）；`CopySkill` 向其追加技能 id（去重）。
- **外来子技能（甜蜜传递）**：`DishInstance` 另持有 `TransferredSkills`（`SkillEffect`(规则+描述) + 来源标签的列表）。甜蜜传递传的**不是整个食物技能 id**，而是「传递子技能所在 skill 内的其他子技能(rule)」——因为已做「一个食物一个 skill」，同一食物的计分/被动子技能与传递子技能同处一个 skill。
- **接收者候选**：`TransferSkills` 的接收者固定为全场其它食物，并从中随机取描述中的 X 个；来源食物自身不能成为接收者。第一子技能的 `actionScope` 只决定该子技能正常执行或被传递后相对接收者的效果范围，不限制甜蜜传递选谁。
- **接收者权重**：非甜蜜传递流派（`archetypeWeights[0]=0`）固定权重 1；甜蜜传递流派（`archetypeWeights[0]>0`）按食物定义形状的占格数 `Shape.CellCount` 加权。多目标逐个无放回抽取，每次从剩余候选重新计算权重；选择全部候选时保持原顺序且不消耗随机数。`TriggerSweetTransfer` 挑选要代触发的来源仍为均权，不应用接收者权重。
- **一个食物一个 skill**：每个食物的 `dish_base.skills` 只引用一个技能，甜蜜传递作为该技能的一个子技能。这样传递 = 把本食物的其他子技能给别人，语义自洽；传递子技能本身被 `EffectsToTransfer` 排除，不会链式传递。
- **甜蜜传递落地（当前均为 OnSettle）**：结算器从候选中选出目标后，先把本次载荷登记到当前计算的待提交列表，再以接收方为中心执行“实例上已持久化 + 本轮此前待提交 + 本次新增”的全部 `OnSettle` 外来子技能。预览只读取这份计算视图，不修改实例；正式结算后由 `BattleSession` 仅将本次 `Effects` 追加到目标 `TransferredSkills` 一次。框架仍兼容 `OnServe`，但当前食物表没有使用。
- **单次结算 Buff 注册**：甜蜜 Buff 只存放在 `ScoreContext`，不写入 `DishInstance`、存档或跨局状态。软糖自身结算后给同列及自身的全部食物挂 Buff；任一被挂载来源每次向 `N` 个最终合法接收者成功传递时，该软糖登记的每份食物倍率均线性 `+0.8 × N`，接收者位置不限。棉花糖自身结算后给下侧投影内全部食物挂 Buff；被挂载来源每次成功传递时额外选择 2 个目标。松露巧克力自身结算后给全场食物挂 Buff；某来源每次发动甜蜜传递时，每个松露各进行 1 次 60% 独立判定，成功则额外选择 1 个目标，因此单个松露的期望额外目标数恒为 0.6，与原目标数及固定目标加成无关。多个软糖分别响应并把倍率加值线性叠加，多个棉花糖的额外目标数相加，多个松露的成功次数相加；额外目标均受候选数量封顶，Buff 不因触发而消耗。
- **成功与失败边界**：只有最终至少选中一个合法目标才算成功并查询/触发 Buff。没有候选、选择器返回空、或只返回非法实例 ID 时，记录 `SweetTransferFailed` 并播放“没有可传递目标”，不执行外来技能、不触发软糖倍率或棉花糖额外目标；Buff 保留供本次结算内后续枫糖代触发再次尝试。
- **优先结算时序**：结算严格按食物顺序执行。高优先级来源若在软糖/棉花糖自身规则之前发动甜蜜传递，不会命中尚未登记的 Buff；Buff 登记之后，同一来源自身传递和枫糖代触发的每次成功传递都会分别响应。
- **代触发甜蜜传递（枫糖/大棒棒糖）**：`TriggerSweetTransfer` 不重跑来源的整个技能，也不触发其他子技能；只代执行来源的 `TransferSkills` 子技能，把同一 skill 内其他可传递子技能交给目标。当前枫糖随机选 3 个来源，大棒棒糖处理同行同列全部来源；来源标签、传递载荷、目标作用域和 `actionCount` 都来自被触发食物自身。每个来源独立结算，某次失败只产生对应失败事件，随后继续下一个来源。
- **结算与生效时机**：实例上已持久化的外来子技能仍随接收方正常结算一次（`SkillRuleEffectSource` 遍历 `TransferredSkills` 的 `OnSettle` 规则，作用域相对接收方计算）；此外，每次 `OnSettle` 甜蜜传递成功后，接收方都会按当时的完整累计列表重结算所有甜蜜传递子技能，不做单轮去重。`OnServe` 传递只把技能追加到实例，等待后续正常结算，不在上菜流程外即时计分。食物结束实例销毁时清除，不跨食物保留。
- **技能来源溯源**：外来子技能带来源标签「来源食物名<甜蜜传递>」，结算明细用 `ScoreSource.TransferredDishSkill` 以来源标签命名该行；食物详情/tips 单独列出每条外来子技能（`【源名<甜蜜传递>】子技能描述`）。运行时技能集里由 `CopySkill` 获得的技能仍用 `skillId → 来源标签` 映射（`GetSkillSource`）。
- **累计重触发的演出归属**：`SkillExecutionTrace.OwnerDishInstanceId` 始终表示当前子技能的历史来源，`RuntimeSelfDishInstanceId` 表示接收并执行技能的食物；若本轮是因为收到一笔新传递而立即重触发累计技能，则另由 `SweetTransferHandoffSourceDishInstanceId`、`SweetTransferHandoffExecutionGroupId`、`SweetTransferHandoffSkillId` 和 `SweetTransferHandoffPayloadCount` 记录这笔传递的真实发送者、批次及新增技能。表现层按「批次 + 真实发送者 + 接收者」只播放一次粒子和发送者触发反馈，并按载荷数只揭示本次新卡片，同时保留所有历史 Owner 的技能效果与来源文案；例如 C 新传给 A 时，B 的旧技能仍执行并显示，但只播放 C→A 的交接粒子。

### 5.3 永久加分

- `DishInstance` 持有 `PermanentFlatBonus`（默认 0）。
- `PermanentAddFlat` 行为：**本次结算即生效**（当次直接进加法区），同时把增量登记到 `ScoreResult`，由 `BattleSession` 结算后写回实例。
- 写回后，`PermanentFlatBonus` 计入下次结算的**基础分**，故本场经营挑战内多次结算会持续累积（当前代表食物为巧克力条）。
- **作用范围**：`DishInstance` 每场经营挑战重建，永久加成**仅在本场经营挑战内**累积，不跨经营挑战/整局持久（棋盘状态不随存档保存）。

### 5.4 有效份数（EffectiveCountAs）

- 每个食物有静态有效份数 `Def.CountAs`（默认 1，`dish_base.countAs`）；`Instances` 按有效份数累加，`PhysicalInstances` 才按实际食物数量统计。
- `AddCountAs` 行为可动态改写：所有子技能都在实际触发时写入 live count-as，并按 `subSkills`/结算执行顺序仅影响其后的规则，不追溯重算已经执行完的技能。法棍与芭菲遵循相同的主动触发时序；这些效果只在当次结算生效，不跨结算持久。
- 计算 live 值时其条件用非 live 计数评估，避免有效份数递归依赖自身。
- 结算中途通过甜蜜传递或技能复制获得的主动 `AddCountAs` 同样在实际触发时生效，只影响后续规则；被动 `AddCountAs` 仍以结算开始时已存在的规则集为准。

### 5.5 技能复制（RNG 副作用）

- `CopySkill` 从候选池随机取 N 个不同技能；当前双层蛋糕从 `cat:cake` 技能池取 3 个。
- `OnSettle` 执行时，结算快照中的选择器先确定本次选中的技能，并让这些技能在当次立即生效；`ScoreResult` 同时保留选择结果，正式结算后由 `BattleSession` 调用 `AddSkill` 写回目标实例。
- 复制候选会排除目标已有技能与 `CopySkill`，避免重复与递归复制。

### 5.6 经营挑战 / 整局历史

- **小局（本场经营挑战经营挑战 = 一场经营挑战 `BattleSession`）**：记录本场已结算过的食物 BaseId 计数 `MealSettledCount[baseId]`。
- **大局（整局 `GameRun`）**：记录整局累计已结算过的食物 BaseId 计数 `RunSettledCount[baseId]`，随存档保存。
- 结算完成（`Settle`）时把本场各菜 BaseId 累加进上述两个计数；这两个计数以**只读快照**注入结算，供 `SameKindInMeal`/`SameKindInRun` 读取（读取的是**本次结算之前**的历史，避免自累加）。

## 6. 金币桥接（经济运营）

结算层是纯 C#，不能引用 `GameRun`。`GrantGold` 不直接改金币，而是：

1. 行为把金币增量写进 `ScoreContext` 的侧效果累加器。
2. `ScoreResult` 暴露 `GoldDelta`（及未来其它侧效果）。
3. `BattleSession.Settle` 汇总；Game 层在结算演出完成后把 `GoldDelta` 写回 `GameRun.Gold`。

预览分（`PreviewScore`）也会算出 `GoldDelta`，但**不入账**（只有正式 `Settle` 才由 Game 层应用）。

## 7. 配置落地（TbSkill + TbSubSkill）

### 7.1 主表 `TbSkill`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 技能ID（主键） |
| subSkills | string | 本技能独占的有序子技能 ID 列表（`|` 分隔） |

> 食物技能效果统一由子表 `TbSubSkill` 表达；`TbSkill` 只保存子技能引用。

### 7.2 子表 `TbSubSkill`（`sub_skill@dish.xlsx`）

一行 = 一条规则；归属与执行顺序由 `TbSkill.subSkills` 的 ID 列表决定。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 规则ID（主键） |
| trigger | SkillTrigger | 触发时机（OnSettle/OnServe） |
| condType | SkillConditionType | 前提类型（None=无前提） |
| condScope | SkillScope | 前提作用域；`Other` 表示全部但不含自身，`CakeBuff` 表示全局欢乐蛋糕层数效果 |
| condUnit | CountUnit | 计数单位（个/种） |
| condMode | CountMode | 计数模式（Per/Reach/Gate） |
| condParam | string | 前提附加参数（如形状 `1x1`、`settled`、比较阈值 `gte:2`/`>=2`、阶梯 `tiers:5\|15\|25`、每 N 个 `div:N`、方向含自身 `include:self`、棋盘格源 `source:board`） |
| actionType | SkillActionType | 行为类型 |
| actionScope | SkillScope | 行为作用域（目标）；`CakeBuff` 用于 `AddLayer` 等全局欢乐蛋糕层数效果，不选择食物目标 |
| actionCount | int | 随机目标数（0=全部） |
| actionValue | list,float | 行为数值 |
| actionParam | list,string | 行为参数（如 `mult`、`cat:xxx`、`skilltype:XXX`、`include:self`、`target:occupiedcells`、`when:transfer`、`modifier:add-targets`、`chance:0.6`） |
| signed | bool | 描述回填数值时是否显示正负号 |
| descTemplate | string | 子技能描述模板 |
| termId | string | 关联术语 ID（可空） |

## 8. 结算接入

- `SkillRuleEffectSource : IScoreEffectSource` 遍历每个食物的运行时技能 → 技能规则 → 求前提 `count` → 产出行为效果条目。
- 前提求值器（`SkillConditionEvaluator`）按 `condType/condScope/...` 用 `Board`、只读历史、食谱快照算 `raw` 再折算 `count`。
- 行为通过 `ScoreContext` 命令改分（`AddFlat/MultiplyBy`、目标食物命令、`GrantGold`、层数命令等），受 `MaxCommandsPerCalculation` 安全阀保护。
- 默认阶段：OnSettle 规则在 `DishSkills` 阶段；跨菜/局级行为可提升到 `AfterAllDishes`/`Final`（由 source 决定 `Phase`）。
- OnServe 规则在 `BattleSession.Serve` 后由一个轻量 serve-time 结算子流程执行（仅处理该实例的 OnServe 规则）。

## 9. 红线

- 结算层保持纯 C#、不引用 Unity/`GameRun`；金币等外部副作用只经 `ScoreResult` 侧效果桥接。
- 不在结算器里写具体技能硬编码分支：新前提/新行为走「枚举 + 求值器/派发器」扩展。
- 顺序依赖用 `order` 与 `Priority` 表达，不依赖隐性行顺序。
- 每新增前提/行为都要补 EditMode 测试（count 计算 / 行为效果 / 组合 / 明细来源）。
