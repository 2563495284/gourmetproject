# 分数结算规则与扩展性

> 面向策划。说明「吃」这一步分数是怎么算出来的、结算按什么顺序执行、风味效果有哪些、以及后续怎么加新效果 / 新来源。
>
> 对应代码目录：`Assets/GameMain/Scripts/Gameplay/Scoring/`。结算层是纯 C#，可单测、同种子可复现，表现层只读取结果做演出。

---

## 1. 一句话理解

分数结算采用「小丑牌式阶段结算」：
**逐个食物结算，每个食物各算各的贡献，全部菜算完后再做一次全局修正，最后取整得到总分。**

不是「全局事件广播」，而是**确定性、可预测、可解释**的流水线。同一个棋盘 + 同一套配置，结算结果永远一致。

---

## 2. 单道菜的计算公式

每个食物的美味值由三段「分数」与一个「倍率」构成：

```
美味值 = 向上取整(((初始分数 + 永久分数) + 临时分数) × 倍率)
```

- **初始分数**：食物自身的固定分（`DishDef.Deliciousness`）。
- **永久分数**：`分数永久+X`（`PermanentAddFlat`）累加，写回 `DishInstance.PermanentFlatBonus`，**结算后不消失**，本场经营挑战内每次结算都作为基础分累计。
- **临时分数**：`分数+X`（`AddFlat`）累加，只作用于本次结算，**总结算后清空**，下次结算从 0 起。
- **倍率**：初始 1（含已持久化的永久倍率 `PermanentMultBonus`），由「倍率 +X」（`AddMultFlat`）与「倍率 ×X」（`AddMult`）共同累积。

> 代码上「初始分数 + 永久分数」合并为累加器的基础值 `Base`（`Deliciousness + PermanentFlatBonus`），临时分数是 `Flat`，倍率是 `Mult`，贡献 = `ceil((Base + Flat) × Mult)`。

> 关键规则：**先把三段分数加完，再乘倍率。** 加法与倍率不会交错影响，「先加后乘」结果确定。

### 倍率如何累积（小丑牌式）

倍率的「+X」和「×X」**按效果触发/编写顺序依次作用**，不区分先加后乘——就像《小丑牌》里加倍率与乘倍率交替生效：

```
初始 1 → +0.4 → ×1.2 → +0.5 → ×1.2
((1 + 0.4) × 1.2 + 0.5) × 1.2 = 2.616
```

> 因此同一技能内多个倍率子技能的**书写顺序**即生效顺序（同阶段同来源按登记序号，即 subSkills 列表下标）。想要特定结果就按目标顺序编排子技能。

### 算例

1 个食物：初始分数 10，带「新鲜（临时 +5）」和「香甜（倍率 ×1.5）」两个标签。

```
((10 + 0) + 5) × 1.5 = 22.5 → 向上取整为 23
```

## 3. 总分公式

所有食物的贡献先求和，再叠加**局级修正**，最后取整：

```
总分 = 四舍五入( (所有食物贡献之和 + 局级加法) × 局级倍率 )
```

- **所有食物贡献之和**（`RawSum`）：每个食物按第 2 节算出贡献并向上取整后相加。
- **局级加法 / 局级倍率**（`FinalFlat` / `FinalMultiplier`）：作用于「全部菜的总和」这一层，由遗物、周规则、装饰品和消耗品 Buff 注入。默认加法 0、倍率 1。
- **取整规则**：每个食物的 `(分数 × 倍率)` 先向上取整（例如 22.5 → 23），局级修正后的最终总分再四舍五入到整数，**0.5 向上进位**。

### 算例

两道菜贡献分别是 22.5 和 30，本局有一个「全局 ×2」的遗物：

```
(22.5 + 30 + 0) × 2 = 105  → 总分 105
```

## 4. 结算顺序（最重要的规则）

### 4.1 阶段顺序

结算分成若干阶段，按下表从上到下依次执行：

| 阶段 | 说明 | 作用范围 |
| --- | --- | --- |
| `BeforeAll` | 全部开始前 | 全局 |
| `BeforeDish` | 每个食物结算前 | 逐菜 |
| `DishBase` | 记录该菜基础分数 | 逐菜 |
| `DishSkills` | 结算**食物技能**（数量无上限） | 逐菜 |
| `DishFlavor` | 结算**食物风味**（多槽，可叠加） | 逐菜 |
| `AfterDish` | 每个食物结算后 | 逐菜 |
| `AfterAllDishes` | 全部菜结算完（分数汇总前）；**欢乐蛋糕层数分段 buff** 在此步应用（见 §8.6） | 全局 |
| `Final` | 局级修正 | 全局 |

「逐菜」阶段会对**每1 个食物**各跑一遍；「全局」阶段整局只跑一次。

> 设计含义：**同1 个食物内，先结算技能，再结算风味。**

### 4.2 菜与菜之间的顺序（结算优先级层级 + 餐桌位置）

逐菜阶段的遍历顺序：**先按结算优先级层级降序，再按餐桌位置从上到下、从左到右**（层级相同再比行 Y、列 X、放置 id）。

- 层级默认 0；风味「甜」使该菜层级 +1、「苦」-1，多风味叠加（`ScoreSnapshot.SettlementLayerOf` 汇总所有 `SettlementLayer` 风味）。层级越大越先结算。
- 层级相同的菜之间，仍按靠左上角先结算。

### 4.3 同一阶段内的顺序

当同一阶段里有多个效果时，按以下优先级稳定排序（前者优先）：

1. **阶段**（`Phase`）
2. **棋盘顺序**（`BoardOrder`，左上优先）
3. **来源类型**（`Dish` → `DishSkill` → `DishFlavor` → `Material` → `TableTag` → `Relic` → `FinalModifier`）
4. **优先级**（`Priority`，数字小的先执行，可正可负）
5. **登记序号**（`Sequence`，先收集到的先执行）

> 策划要点：如果两个效果在同一阶段、需要明确先后，用**优先级**字段控制（小的先）。不要依赖「配置表的行顺序」之外的隐性约定。

## 5. 风味效果类型（现有内置）

风味在配置里用 `EffectType`（效果类型）+ `EffectValue`（效果数值）描述。当前内置效果包括：

| EffectType | 含义 | 公式（X = EffectValue） |
| --- | --- | --- |
| `AddFlat` | 本菜加法区 +X | 加法 += X |
| `AddMult` | 本菜倍率 ×X | 倍率 ×= X |
| `PerAdjacentDish` | 每个相邻菜，本菜 +X | 加法 += X × 相邻菜数量 |
| `PerEmptyCell` | 棋盘每个空格，本菜 +X | 加法 += X × 棋盘空格数 |
| `PerOccupiedCell` | 本菜每占一格，本菜 +X | 加法 += X × 本菜占格数 |
| `PerDishOnBoard` | 棋盘每多1 个食物，本菜倍率按复利涨 | 倍率 ×= (1 + X) 的「棋盘菜数」次方 |

其中 `PerDishOnBoard` 是复利：棋盘上有 N 道菜时，倍率因子为 `(1 + X)^N`。

> 还有两个「局级效果」（不挂在食物技能/风味上，给遗物 / 周规则用）：
> - `AddFinalFlat`：总分加法区 +X（作用在 `Final` 阶段）。
> - `MultiplyFinal`：总分倍率 ×X（作用在 `Final` 阶段）。

### 配置字段说明

风味来自 Luban 配置 `TbFlavor`，运行时对应 `FlavorDef` 并通过 `FlavorEffectType` 派发。食物技能来自 `TbSkill` + `TbSkillRule`，运行时对应 `SkillDef` / `SkillRuleDef`，由规则系统解释。

| 字段 | 用途 |
| --- | --- |
| `EffectType` | 效果类型，对应上表 |
| `EffectValue` | 效果主数值 X |
| `EffectParam` | 效果次要参数（如分类过滤、目标 id），多数效果用不到 |
| `TermId` | 关联专有名词 id，非空时食物详情额外展示 |

> 风味挂食物，可叠加。技能挂在食物本体上，数量无上限，具体效果写在 `TbSkillRule`。

## 6. 可解释性（给 UI / 调试 / 数值验证）

每次结算输出两类记录，方便做结算演出、复盘和数值校对：

- **结算明细（`ScoreLine`）**：记录「**哪个来源**在**哪个阶段**对**哪道菜 / 哪一格**做了什么改动」，含改动前后数值。例如「新鲜：美味值 +5」。
- **生命周期事件（`ScoreEvent`）**：记录「发生了什么」的时间线（开始结算、某道菜开始 / 完成、某效果开始 / 结束、命令执行），不直接改分数，用于演出和回放。

> 数值需求：每加一个新效果，都应保证它在明细里能被解释清楚（来源、阶段、数值），否则 UI 无法展示、QA 无法验证。

## 7. 扩展性：后续怎么加东西

结算管线设计成「**加效果不用改结算器**」。常见的三种扩展：

### 7.1 加一个新的风味效果类型

适用：想要一种全新的「数值规则」（例如「每有一个同类菜 +X」）。

1. 在 `FlavorEffectType` 枚举（配置侧 + 玩法侧）新增一项。
2. 写一个实现 `IScoreEffect` 的效果类，在 `Apply` 里通过 `ctx.AddFlat() / ctx.MultiplyBy()` 等改分。
3. 在 `FlavorEffectRegistry.CreateDefault()` 注册映射。
4. 配置表里给风味填上新的 `EffectType`。

策划侧只需要：确定**公式**、**用哪个数值字段**（`EffectValue` / `EffectParam`）、以及它**属于哪个阶段**（风味在 `DishFlavor`）。食物技能的新公式优先扩展 `SkillConditionType` / `SkillActionType`。

### 7.2 加遗物 / 周规则 / 装饰品和消耗品这类「非食物技能/风味」来源

适用：效果不挂在某个菜上，而是「本局生效」「满足条件触发」。

实现一个 `IScoreEffectSource`，把它要产生的效果收集成若干条目（指定**阶段**、**来源类型**、**作用对象**、**优先级**）。例如：

- 「全局结算分 ×2 的遗物」→ 在 `Final` 阶段产出一个 `MultiplyFinal` 效果。
- 「每个食物额外 +2 的撒盐遗物」→ 在 `AfterDish` 阶段产出一个逐菜加法效果。

这些来源在创建 `BattleSession` / `ScoreCalculator` 时注入，不污染食物技能/风味体系。

> 当前 `BattleSession` 已经预留了 `FinalFlat` / `FinalMultiplier` 两个局级修正入口，简单的「整局加分 / 整局倍率」装饰品和消耗品可以直接写这两个值，不必新建来源。

### 7.3 连锁效果（触发时再触发一个效果）

适用：「某效果触发时，额外引发另一个效果」。

效果内部通过 `ctx.SubmitCommand(new ResolveScoreEffectCommand(另一个效果条目))` 提交连锁，结算器会在当前效果结束后立即解析它，并正确归属到当前来源 / 阶段 / 格子，明细不会错位。

> 安全阀：单次结算的命令执行数有上限（防止效果互相无限触发）。设计连锁时避免出现环形互相触发。

## 8. 红线与约束

- **结算层不写具体玩法内容的硬编码分支**：新规则走「新效果 + 注册」或「新来源」，不要往结算器里塞 `if (标签 == "辣条")`。
- **结算层保持纯 C#**：不引用 Unity / GameFramework，保证可单测、可复现。
- **改分只能走上下文**：效果通过 `AddFlat / MultiplyBy / AddFinalFlat / MultiplyFinalBy / SubmitCommand` 改分，不要绕过上下文直接改结果，否则明细会缺失。
- **新效果必须配套测试**：至少覆盖总分、执行顺序或明细来源（参考 `Tests/EditMode/ScoreCalculatorTests.cs`）。
- **顺序依赖要显式**：同阶段先后用 `Priority` 表达，不要依赖隐性顺序。

## 8.5 技能规则、跨菜与副作用（食物技能系统）

食物技能的「前提×行为」组合规则见 [技能.md](技能.md)。它对本管线的扩展：

- **多来源**：`SkillRuleEffectSource` 把食物技能规则转成效果条目。前提求值 `SkillConditionEvaluator` 产出 `count`，行为 `SkillRuleEffect` 按 `count` 派发。
- **每菜独立累加器 + 延迟定稿**：`ScoreContext` 为每个食物保存独立累加器，所有逐菜阶段跑完后由 `FinalizeDishes()` 统一求和。因此技能可以**改到别的食物**：`AddFlatTo` / `MultiplyTo` / `AddMultFlatTo`（倍率线性 +X，明细类型 `DishMultiplierAdd`）/ `TransferScore`（加法层按比例转移）/ `AddExtraSettlement`（目标食物技能额外触发 N 次）。
- **有效份数（EffectiveCountAs）**：`Instances` 按每个食物的 `EffectiveCountAs` 累加（默认 `DishDef.CountAs`，默认 1），`PhysicalInstances` 按实际食物数量统计。主动 `AddCountAs` 在对应规则实际触发时更新 live 值，只影响后续规则，并只在当次结算生效。
- **永久加分/倍率**：`PermanentAddFlat` / `PermanentAddMult` 本次结算即计入（进加法区/倍率），并把增量登记到 `ScoreResult.PermanentFlatDeltas` / `PermanentMultDeltas`，由 `BattleSession` 写回 `DishInstance.PermanentFlatBonus/PermanentMultBonus`；下次结算作为基础分/倍率初值累积（仅限本场经营挑战）。
- **对外副作用（预览安全）**：`GrantGold` / 全局层数（`AddLayer`/`ConsumeLayer`）/ `RecordSkillTransfer`（技能传递）在结算中**只累积**到 `ScoreResult.GoldDelta` / `HappyCakeLayerDelta` / `SkillTransfers`，不直接改实例；`PreviewScore` 因此纯净可复现，正式 `Settle` 后由 `BattleSession` 应用、`BattleForm` 写回 `GameRun.Gold` 与大局历史。
- **全局欢乐蛋糕层数**：`BattleSession` 持有整场经营挑战共享的 `HappyCakeLayers`，经 `ScoreSnapshot.InitialHappyCakeLayers` 注入结算；`LayerCount` 前提读「初值+增量」，支持 `cap:N` 封顶。
- **RNG 副作用（技能复制/临时复制/甜蜜传递）**：`CopySkill` / `TempCopyDish` / `TransferSkills`(OnServe) / `TriggerSweetTransfer`(OnServe) 需要随机流，`ServeRuleResolver` 只登记请求（候选技能池 / 待克隆源 / 甜蜜传递候选目标+外来子技能载荷），由 `BattleSession.Serve` 用注入的 `IRandomStream` 落地。甜蜜传递在候选（作用域内有食物且非自身的菜）中按权重无放回取 `actionCount` 个（0=全部）：非甜蜜传递流派（`archetypeWeights[0]=0`）权重固定为 1，甜蜜传递流派（`archetypeWeights[0]>0`）权重为食物定义形状的 `Shape.CellCount`；全选时保持候选顺序且不消耗随机数。载荷是「传递子技能所在 skill 内的其他子技能(rule)」，接收方把这些外来子技能挂到自身（`DishInstance.TransferredSkills`），并记录来源标签「来源食物名<甜蜜传递>」。`OnSettle` 传递成功时，当前载荷先加入计算视图，再立即以接收方为中心重结算其已持久化、本轮此前获得及本次新增的全部 `OnSettle` 甜蜜传递子技能；同轮多次接收会多次重结算全量列表，但每次新载荷只在正式结算后持久化一次。`OnServe` 传递只追加技能，等待后续正常结算。`TriggerSweetTransfer` 不传自己的子技能，而是均权选择作用域内带甜蜜传递的食物，让其各自按原 `TransferSkills` 规则登记一次传递请求（大棒棒糖用同行同列筛选）；来源选择不使用接收者占格权重。食物结束时清除外来子技能。
- **技能来源溯源与明细**：`DishInstance` 持有 `skillId → 来源标签` 映射；`SkillRuleEffectSource` 收集技能效果条目时，若该技能有来源标签则用 `ScoreSource.TransferredDishSkill`（明细行以来源标签命名），否则用 `ScoreSource.DishSkill`。表现层（食物详情/tips）技能卡标题同样优先显示来源标签。
- **只读历史/食谱**：`IScoreHistory` 注入 `ScoreSnapshot`，供「大局/小局相同」「食谱检测」读取（读本次结算之前的状态）。
- **上菜时**：OnServe 规则由 `ServeRuleResolver` 在 `BattleSession.Serve` 后处理（层数/技能传递/金币/技能复制/临时复制）。

## 8.6 欢乐蛋糕层数分段 buff（全局分段加成）

一个「根据全局层数分段」的全局 buff，插在**所有食物/风味/标签结算之后、分数汇总之前**（`AfterAllDishes` 阶段），每场经营挑战层数从 0 起（由 `BattleSession.HappyCakeLayers` 满足清零）。

- **配置**：Luban 表 `TbCakeLayerBuff`（`dish.xlsx` 的 `cake_layer_buff` sheet，由外部策划配表维护）。每档：`threshold`（层数阈值，`≥` 生效）、`category`（作用分类，如 `cake`）、`effectType`（复用 `SkillActionType`）、`valuePerLayer`（每层系数）、`order`（同阈值内顺序）。
- **来源**：`CakeLayerBuffSource`（内置于 `ScoreCalculator.CollectEntries`，与 `SkillRuleEffectSource` 并列）；表为空则不产出任何条目。产出**一条** `AfterAllDishes`、`Dish==null` 的全局条目，效果持有档位列表，来源 `ScoreSource.BoardTag("cake_layer_buff","欢乐蛋糕层数")`。
- **应用**：读 `ctx.CurrentHappyCakeLayers`，按阈值升序遍历满足档（可多档同时生效、依次执行、明细归属同一来源），对 `CategoryDishes(category)` 的每个食物按 `effectType` 应用 `value = valuePerLayer × 层数`：`AddFlat→AddFlatTo`、`AddMultFlat→AddMultFlatTo`、`AddMult→MultiplyTo`。
- **默认三档**：≥1 层 `AddFlat 5`（基础分 +5×层）；≥50 层 `AddMultFlat 0.1`（倍率 +0.1×层）；≥100 层 `AddMult 0.02`（倍率 ×(0.02×层)，如 100 层=×2）。因升序执行，`AddMult` 乘的是已叠加 `AddMultFlat` 后的倍率。

## 8.7 风味（第一批）

详见 [风味](游戏设计/风味与材质.md)。对本管线的扩展：

- **多风味**：`DishInstance.FlavorIds`（列表，可叠加）。风味走 `FlavorEffectSource` + `FlavorEffectType`，逐个风味在 `DishFlavor` 阶段派发。
- **结算优先级层级（甜/苦）**：`FlavorEffectType.SettlementLayer` 风味不产生分数效果，仅由 `ScoreSnapshot` 在结算前汇总成层级、决定菜的遍历顺序（见 §4.2）。甜=+1、苦=-1。
- **鲜（优先出菜）**：`FlavorEffectType.ServePriority` 不进入分数阶段。选定食谱槽后，先完成可摆放与系统规则过滤；若剩余候选中存在鲜菜，则只在鲜菜内按原占格权重抽取，否则回退全部普通候选。多层鲜不继续提高优先级。
- **麻（上菜旋转）**：`FlavorEffectType.Rotate` 不产生分数效果；在 `BattleSession.Serve` 读取，把食物形状**逆时针** n×90° 旋转后再找合法放置（`DiningTable.FindValidPlacementsRotatedCcw`，放不下回退不旋转）。旋转改 `OccupiedCells`，同行/同列/相邻/形状匹配自动跟随。
- **酸（未上菜食谱加倍率）**：`RecipeFlavorEffectSource` 在 `BeforeAll` 遍历仍留在食谱中的菜；每层 `RecipeAddMultFlat` 都使场上全部已上菜食物倍率 `+0.5`，可逐层叠加。已上菜的酸不触发此效果。
- **咸（随机额外结算）**：每道场上食物的每层 `ExtraSettlementChance` 在正式结算中独立掷 20%；每次成功只再次执行本菜的原生 `OnSettle` 技能，不重复基础分、其他风味、复制技能或甜蜜传递获得的技能。技能产生的分数、倍率及对其他菜的影响直接叠加到当前结算；咸本身不递归掷骰，预览不计随机收益，明细记录触发次数。

## 9. 关键类速查

| 类 / 文件 | 职责 |
| --- | --- |
| `ScoreCalculator` | 编排：收集效果 → 按阶段 / 顺序稳定执行 → 输出结果 |
| `ScoreSnapshot` | 一次结算的只读输入（棋盘、配置、局级修正、额外来源、`IScoreHistory`） |

| `CakeLayerBuffSource` / `CakeLayerBuffDef` | 欢乐蛋糕层数分段 buff：`AfterAllDishes` 全局条目，按全局层数分段累计应用到指定分类 |

| `FlavorEffectRegistry` | 把 `FlavorEffectType` 派发到具体风味效果实现 |
| `IScoreEffectSource` | 把某类来源（食物技能/风味 / 遗物 / 周规则…）转换成效果条目 |
| `ScoreResult` | 结算结果：逐菜明细、`RawSum`、局级修正、`Total`、`ScoreLine`、`ScoreEvent`，及副作用增量（`GoldDelta` / `HappyCakeLayerDelta` / `PermanentFlatDeltas` / `PermanentMultDeltas` / `SkillTransfers`） |
| `ScorePhase` | 阶段枚举（决定默认执行顺序） |
