# 游戏设计

## 核心循环

玩家在一局中沿着预生成的行动序列前进。每个行动可能进入美食挑战、事件或奖励界面；美食挑战会根据当前进度、行动难度、道具和事件修正生成目标分、奖励和随机池要求。玩家通过菜谱上菜、在胃部棋盘中结算菜品与格子标签来获得分数，达成目标后获得金币、菜品、道具或胃部碎片等奖励。

核心资源关系：

- 菜品：类似道具的构筑对象，提供形状、分数和标签。
- 菜谱：决定可被上菜随机系统抽取的菜品集合。
- 胃部棋盘：决定菜品摆放空间、格子标签和扩展边界。
- 道具：提供局级、上菜、标签结算、最终结算和奖励阶段的修正。
- 隐藏分：控制目标分、菜品、道具和胃部碎片的投放节奏。

## 行动与日程

### 行动类型

行动从外观和奖励结果上分为：

- 美食（奖励金币）
- 美食（奖励胃部碎片）
- 美食（奖励道具）
- 美食（奖励菜品）
- 更难美食（可奖励金币、胃部碎片、道具或菜品）
- 事件
- 奖励

美食行动的难度至少包含普通、难、Boss 等档位。难度会参与目标分、金币范围和随机奖励隐藏分的计算。

### 行动组合

行动组合是配置层面的日程片段，包含若干行动类型和对应时间随机范围，不限定必须是三个行动。示例：

- 普通美食组：美食（奖励金币）+ 美食（奖励胃部碎片）+ 美食（奖励道具）
- 普通更难美食组：美食（奖励金币）+ 美食（奖励胃部碎片）+ 更难美食（奖励道具）
- 事件美食组：事件 + 美食（奖励道具）
- 纯奖励组：奖励

### 行动序列生成

一局开始时通过静态随机生成行动组合序列，例如：普通美食组 -> 普通更难美食组 -> 纯奖励组。序列生成遵循：

- 先处理高优先级的固定约束，再随机填充剩余位置。
- 可以配置某类行动组合在指定区间内出现，例如纯奖励组在第 3-6 个行动出现一次、在第 10-12 个行动出现一次。
- 可以配置窗口型约束，例如事件美食组在每 10 个行动中的第 2-8 个行动随机出现 1-2 个。
- 剩余位置按权重随机行动组合。
- 连续两次不能出现相同的行动组合。

## 分数、隐藏分与奖励

### 基础隐藏分

基础隐藏分用于统一控制局内难度和奖励投放节奏：

- 基础隐藏分 = f（游戏进度、行动加成、道具加成）
- 游戏进度通常由天数、周数或行动序号决定。
- 行动加成来自行动类型、行动难度、事件结果或 Boss 机制。
- 道具加成来自被动道具、主动道具和特殊标签效果。
- 具体函数可以按进度分段配置。

### 派生隐藏分

不同系统基于基础隐藏分派生各自的要求值：

- 目标分 = f（基础隐藏分、行动加成、道具加成）
- 菜品隐藏分 = f（基础隐藏分、行动加成、道具加成）
- 道具隐藏分 = f（基础隐藏分、行动加成、道具加成）
- 胃部碎片隐藏分 = f（基础隐藏分、行动加成、道具加成）

目标分用于美食挑战达标判断。菜品、道具和胃部碎片隐藏分用于筛选各自随机库中的候选项。所有派生函数都可以按进度分段，以便控制前中后期投放曲线。

### 局内奖励

局内奖励类型包括金币、三选一菜品、三选一被动道具、主动道具、三选一胃部碎片等。一般结构为金币 + 一个主奖励（菜品、道具、碎片）+ 随机附加奖励（可能为空）。

金币规则：

- 金币一般都会发放，是购物、刷新等系统的通用货币。
- 金币上下限由美食难度（普通、难、Boss）和游戏进度共同决定。
- 在上下限范围内纯随机取值。
- 若奖励随机池完全为空，部分奖励可折算为金币，并输出配置警告。

非金币奖励规则：

- 菜品奖励使用菜品隐藏分随机。
- 被动道具奖励使用统一道具随机池，并可接入道具隐藏分、来源品质分布和特殊标记筛选。
- 主动道具可以按来源和特殊标记纯随机，也受持有上限影响。
- 胃部碎片奖励使用胃部碎片隐藏分随机。

## 菜品与标签

### 菜品属性

菜品是类似道具的构筑对象，主要属性包括：

- 占空间：以格子为基础的空间占据，不同菜品形状不同。
- 基础分数（美味度）：用于技能结算以及最终分数结算。
- 初始分：菜谱生成时用于累计判断初始菜谱是否达到要求初始分。
- 标签：每个菜品拥有的标签数不一定相同。

### 标签类型

- 固有标签：获得菜品时，若无额外条件，会获得带有固有标签的菜品。
- 唯一标签 A：每个菜品有 1 个上限，若再次获得唯一标签 A，会替换原来的标签。特殊道具可以解除上限设定。
- 唯一标签 B：规则同唯一标签 A。

标签涉及游戏专有名词时，需要额外展示说明。例如鼠标悬停或选中卡牌时，除了展示卡牌信息，还要展示名词解释。

## 菜谱与随机菜品

### 初始菜谱

- 初始会根据每个角色设立一个初始菜谱。
- 初始菜谱会配置一些固定菜品。
- 初始菜谱中部分菜品并非固定，开局前展示初始菜谱可能包含的菜品种类，部分菜品需要解锁。
- 其余菜品会从可能包含的菜品种类中按权重放回随机，部分菜品会设定最多被随机的次数。
- 菜谱有一个要求初始分，每个菜品也有初始分。每次随机后判断已随机菜品的初始分之和，若大于等于要求初始分，随机结束；若小于，则继续随机。

### 菜品库

- 菜品库是纯配置的随机菜品库。
- 每个菜品都有隐藏分范围、基础权重和价格。
- 隐藏分均值取隐藏分上下限的均值。
- 菜品的标签 A、标签 B 不同时，视为不同菜品，拥有不同的隐藏分范围。

### 随机菜品

每当需要一个菜品展示给玩家选择或获得时：

1. 根据当前进度、行动修正、事件修正、道具修正和随机修正，确立一个要求隐藏分。
2. 从菜品库中筛选隐藏分范围包含该要求隐藏分的菜品。
3. 每个菜品权重为要求隐藏分 `a` 和隐藏分均值 `b` 差值的函数：`w = 基础权重 / max(|a-b|, c)`，其中 `c` 是根据不同进度配置的常数。
4. 同时展示多个菜品时，不放回随机；若全部取完，则全部放回再随机。

## 棋盘（胃）

### 大小

- 每个角色有一个固定的初始胃部大小，可能会根据菜谱变化。
- 每个角色都有一个胃部最大大小，设定为长 `n`、宽 `m`。

### 胃部碎片库

- 配置一个胃部碎片库。
- 碎片方向不允许旋转，例如 `1x2` 和 `2x1` 是两个碎片。
- 部分胃部碎片格可能带有强化标签，分开配置。
- 每个胃部碎片有自身权重、隐藏分范围和价格。
- 隐藏分均值取隐藏分上下限的均值。

### 随机胃部碎片

在需要展示或给玩家胃部碎片奖励时：

1. 检测玩家的最大胃部大小和当前胃部大小。
2. 若已达到最大胃部大小，将碎片按隐藏分分段线性折算为金币。
3. 若未达到最大胃部大小，从胃部碎片库中筛选可以放入当前胃部扩展范围、且隐藏分范围包含要求隐藏分的碎片。
4. 每个碎片权重为要求隐藏分 `a` 和隐藏分均值 `b` 差值的函数：`w = 基础权重 / max(|a-b|, c)`，其中 `c` 是根据不同进度配置的常数。
5. 同时展示多个胃部碎片时，不放回随机；若要展示 3 个但只有 2 个符合要求，则展示 2 个。
6. 如果经过筛选后仍随机不到，输出配置错误，提示策划排查。

### 扩展胃部

- 扩展胃部时通过 UI 直接限制玩家，若扩展后大于最大长宽，则不能扩展。
- 扩展胃部必须贴着原来的胃部扩展，不能分割开来。

## 上菜与结算

### 上菜

1. 根据棋盘空位，筛选出可以被塞入棋盘的菜品。
2. 菜品允许 90 度任意翻转。
3. 根据权重，从可塞入棋盘的菜品中随机。权重正比于这些菜初始的格子数，也可以被道具等效果修正。
4. 每个菜只可以被上一次，除非有特定标签或道具效果。

### 标签结算

1. 若无特殊标签，按照从上到下、从左到右确立所有棋盘格的结算顺序。
2. 多个棋盘格为同一个菜品时，只在第一次结算菜品标签，格子可以结算多次。
3. 先结算菜品标签，再结算格子标签。

### 分数结算

若无特殊标签，按照从上到下、从左到右的顺序，把所有分数加合作为总分数。主动道具、被动道具、标签和 Boss 机制可以在最终结算前追加加法、乘法或达标修正。

## 道具

### 术语

1. 道具定义：配置表中的静态数据，包含名字、描述、图标、类型、品质、特殊标记、权重、效果与上限。
2. 道具状态：单局运行中的持有数据。道具生命周期只有「存在 / 不存在」，没有数量消耗的中间态。被动道具同一 id 唯一一份，用当前等级表示升级；主动道具同一 id 可持有多份，每份是一个独立实例。
3. 获得道具：把一个道具定义结算到道具状态上。被动道具表现为首次获得或升级；主动道具表现为新增一份实例，到达持有上限则折算金币或重抽。
4. 随机池：某次奖励、事件或商店刷新可被抽取的道具集合。所有随机都走统一筛选与权重，避免不同系统规则漂移。

### 被动道具

被动道具参数：

- 技能：具体能力是什么，由效果类型和参数描述。
- 品质：表征稀有度与投放节奏。品质越高，一般越难出现，但不直接等于数值更强。
- 特殊标记：可能在某些事件、Boss 奖励或流派定向奖励中被随机到。
- 等级：等级有上限。越高效果越强，不一定只有数值变化，也可能有机制变化。
- 等级权重修正：已持有但未满级时，本道具的再次出现权重会被修正。
- 解锁条件：部分道具一开始不会解锁，需要满足指定条件。

被动道具升级：

- 首次获得后加入持有列表，显示为“获得道具”。
- 再次即将获得同一道具时，如果未满级，展示为“道具升级”。
- 升级会强化已有道具，可以是数值强化，也可以是新增机制。
- 满级后不再进入普通随机池；若特殊事件强制给到满级道具，则折算为金币或重新抽取。

被动道具触发：

- 构建战斗时：修改本局棋盘、菜谱、目标分、上菜次数等局级参数。
- 上菜前后：修改候选菜权重、额外生成菜、改变摆放结果。
- 标签结算前后：追加标签效果、修改某类菜的分值。
- 最终结算前：追加最终加法、乘法或达标修正。
- 奖励/商店刷新时：修改奖励池、价格、品质分布或额外选项。

UI 展示：

- 原型图最右侧为被动道具列表。
- 默认展示图标、品质边框、等级角标。
- hover/click 展示详情：名称、当前等级效果、下一级效果、特殊标记说明。
- 满级显示 MAX。

### 主动道具

主动道具参数：

- 技能：具体能力是什么，由效果类型和参数描述。
- 特殊标记：可能在某些事件以及 Boss 奖励中被随机到。
- 触发时机：在某些阶段可以触发，例如上菜前、上菜后、吃之前、结算后、奖励界面。
- 持有上限：某些主动道具有当前持有上限，同时最多持有几份实例。到达上限后不再能被随机出，直到用掉手上的实例。约束只看「当前持有几份」，用掉一份就腾出名额，又能被抽到；不设「单局累计获得上限」这种用掉也不恢复的限制。
- 使用即移除：主动道具没有「数量消耗」概念，使用后该实例直接从持有列表移除。需要「反复可用、用了还在」的能力应做成被动道具。

主动道具使用：

- 原型图右下角为主动道具列表。
- 简单主动道具点击后立即生效，例如清空棋盘、额外上菜。
- 复杂主动道具点击后进入选择模式，例如选择一个菜、一个格子或一本菜谱。
- 不满足触发时机时置灰，并展示不可用原因。
- 同一 id 的多份实例在 UI 上聚合为一个槽，用角标 xN 表示份数；用完最后一份即从列表移除。

随机主动道具：

- 特殊事件会从带有特殊标记的道具中随机。
- 随机时都是不放回随机。
- 若达到持有上限，则从候选池中剔除。

### 统一随机规则

所有奖励、事件、商店都使用统一随机池。

筛选顺序：

1. 类型筛选：被动/主动。
2. 解锁筛选：未解锁的道具不进入池。
3. 来源筛选：特殊事件只允许指定特殊标记。
4. 隐藏分筛选：当来源配置要求道具隐藏分时，只保留隐藏分范围包含要求值的道具。
5. 上限筛选：被动满级、主动达到持有上限的道具不进入池。

权重计算：

- 基础权重来自配置。
- 品质分布由来源决定，例如普通奖励、Boss 奖励、商店、特殊事件。
- 若使用道具隐藏分，权重可叠加要求隐藏分和道具隐藏分均值差值的修正。
- 已持有被动但未满级时，乘以等级权重修正。

同时展示多个道具时，不放回随机。如果随机范围内没有道具：

- 先扩大到同来源的全部品质。
- 再没有时扩大到整个已解锁道具库。
- 仍然没有时折算为金币，并输出配置警告，方便策划排查。

### 道具表设计

主表：`TbItem` / `GameConfig/Datas/item.xlsx`

- `id`：唯一 id。
- `name`：显示名。
- `desc`：基础描述，可写当前 1 级效果。
- `kind`：`Passive` 被动 / `Active` 主动。
- `quality`：品质，`Common` / `Uncommon` / `Rare` / `Epic` / `Legendary`。
- `specialTags`：特殊标记，多个标记用 `|` 分隔，例如 `BossReward|SpicyBuild`。
- `maxLevel`：最大等级。被动道具大于 1 时可升级；主动道具一般为 1。
- `nextLevelWeightMultiplier`：已持有但未满级时，再次进入随机池的权重倍率。
- `unlockCondition`：解锁条件 id，空串表示默认解锁。
- `triggerTiming`：主动触发时机，`BeforeServe` / `AfterServe` / `BeforeEat` / `AfterSettlement` / `RewardScreen`；被动填 `None`。
- `acquireLimit`：已废弃字段，运行时不再使用（保留列以兼容现有表）。主动道具上限只看 `holdLimit`。
- `holdLimit`：当前持有上限（主动道具同时最多持有几份实例），`<=0` 表示无限制。
- `baseWeight`：随机基础权重。
- `hiddenScoreMin`：道具隐藏分下限。
- `hiddenScoreMax`：道具隐藏分上限。
- `effectType`：效果类型，由程序注册表分发。
- `effectValue`：主数值参数。
- `effectParam`：额外参数，例如标签 id、菜品 id、流派关键词等。
- `icon`：图标资源路径。

品质概率不写在道具表中，放在奖励来源配置中：

- 普通奖励、Boss 奖励、商店、特殊事件应分别配置品质分布。
- 当前阶段可先在程序中给默认分布，后续扩为 `TbItemPool` 或事件/周配置字段。

特殊标记只负责筛选，不直接改变权重：

- 例如 `SpicyBuild` 表示可以被麻辣流派事件抽到。
- `BossReward` 表示可以进入 Boss 奖励定向池。

效果参数约定：

- `FinalAddFlat`：`effectValue` 为每级最终加分。
- `FinalAddMult`：`effectValue` 为 1 级乘区倍率，升级按增量叠加。
- `TagBonus`：`effectValue` 为加分，`effectParam` 写目标标签 id。
- `ClearBoard`：不需要额外参数。
- `ExtraServe`：`effectValue` 表示额外上菜次数，当前先按 1 次处理。
