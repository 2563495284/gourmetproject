# 菜品
类似于道具
## 属性
- 占空间：以格子为基础的空间占据，类似于背包乱斗的道具，不同菜品形状不同
- 基础分数（美味度）： 技能结算以及分数结算
- 标签，每个菜品拥有的标签数不一定相同。固有标签：获得菜品时，无额外条件时，会获得带有固有标签的菜品。

# 标签
  - 固有标签：
    - 获得菜品时，无额外条件时，会获得带有固有标签的菜品
  - 唯一标签A：
    - 唯一标签A每个菜品有1上限，若再次获得唯一标签A时，会替换原来的
    - 特殊道具可以解除上限设定
  - 唯一标签B：
    - 规则同A
  - 标签涉及到游戏专有名词时，需要额外展示：例如杀戮尖塔中，鼠标select over卡牌时，不仅有卡牌消息，卡牌右上角还有名词介绍例如灵体，多重护甲等

# 菜谱
1. 初始菜谱
  - 初始会根据每个角色，设立一个初始菜谱
  - 初始菜谱会配置一些固定菜品
  - 初始菜谱中一些菜品并非固定，开局前展示初始菜谱可能包含的菜品种类（部分菜品需要解锁）
  - 其余会从可能包含的菜品种类中按权重放回随机（部分菜品会设定最多被随机的次数）
  - 菜谱有一个要求初始分，每个菜品也有个初始分，每次随机后，会判断已随机出来菜品的初始分之和，若大于等于要求初始分，随机结束；若小于，则继续随机
2. 菜品库
  - 纯配置的随机菜品库
  - 每个菜品都有一个隐藏分范围，以及基础权重，价格
  - 取上下限为隐藏分均值
  - 菜品：菜品的标签A、标签B不同，视为不同菜品，拥有不同的隐藏分范围
3. 随机菜品：
  - 每当需要一个菜品展示给玩家选择或获得时，会根据当前的进度、事件修正、纯随机修正，确立一个要求隐藏分
  - 去随机菜品库中，查看隐藏分范围包括此要求隐藏分的菜品，有概率被随机出来
  - 每个菜品权重为要求隐藏分a和隐藏分均值b差值的函数w=基础权重/max「|a-b|，c」（c根据不同进度，是一个常数值）
  - 同时展示多个菜品时，需不放回随机（若全部取完，则全部放回再随机）


# 棋盘(胃)
1. 大小
  1. 每个角色有一个固定的初始大小的胃
    - 可能会根据菜谱有变化
  2. 每个角色都有一个胃部的最大大小
    - 设定为长n，宽m
2. 扩展
  1. 胃部碎片库
    - 配置一个胃部碎片库
    - 碎片方向不允许旋转，如1x2和2x1是两个碎片
    - 部分胃部碎片格可能带有强化标签，分开配置
    - 每个胃部碎片有自身的权重，隐藏分范围，价格
    - 取上下限为隐藏分均值
  2. 随机胃部碎片（某随机机制）
    - 在需要展示或给玩家棋盘碎片奖励时，会检测玩家的最大胃部大小和当前胃部
      - 若以达到最大胃部大小时，会将碎片按隐藏分分段线性折算为金币
      - 没达到时，继续进行下部分操作
        - 从已有的胃部碎片库中，筛选出可以被放入的碎片，且隐藏分范围包括此要求隐藏分的碎片
        - 每个碎片权重为要求隐藏分a和隐藏分均值b差值的函数w=基础权重/max「|a-b|，c」（c根据不同进度，是一个常数值）
    - 同时展示多个棋盘碎片时，需不放回随机（若要展示3个，只有2个符合要求，那么展示2个）
    - 如果进入第二步还随机不到，报个错，让策划知道
  3. 扩展胃部
    - 在扩展胃部时，以ui形式直接限制玩家，若扩展后大于最大长宽时，不能扩展
    - 扩展胃部必须基于贴着原来的胃部扩展，不能分割开来。
# 上菜和结算
  1. 上菜
    1. 根据棋盘的空位，筛选出可以被塞入棋盘的菜
      - 允许90度任意翻转
    2. 根据权重，从这些可以被塞入棋盘的菜中随机
      - 权重正比于这些菜初始的格子数
      - 权重可以被道具等修正
    3. 每个菜只可以被上一次（除非特定标签）
  2. 标签结算
    1. 若无特殊标签，按照从上到下，从左到右，确立所有棋盘格的结算顺序
    2. 多个棋盘格为同一个菜品时，只在第一次结算菜品标签，格子可以结算多次
    3. 先结算菜品的标签，再结算格子标签
  3. 分数结算
    1. 若无特殊标签，按照从上到下，从左到右，把所有分数加合作为总分数
# 道具
## 术语
1. 道具定义：配置表中的静态数据，包含名字、描述、图标、类型、品质、特殊标记、权重、效果与上限。
2. 道具状态：单局运行中的持有数据，包含当前等级、当前数量、累计获得次数、本周/本局使用次数。
3. 获得道具：把一个道具定义结算到道具状态上。被动道具可能表现为首次获得或升级；主动道具通常表现为数量增加。
4. 随机池：某次奖励、事件或商店刷新可被抽取的道具集合。所有随机都走统一筛选与权重，避免不同系统规则漂移。

## 被动道具
1. 被动道具有多个参数
  - 技能：具体能力是什么，由效果类型和参数描述。
  - 品质：表征稀有度与投放节奏。品质越高，一般越难出现，但不直接等于数值更强。
  - 特殊标记：可能在某些事件、Boss 奖励或流派定向奖励中被随机到。
  - 等级：等级有上限。越高效果越强，不一定只有数值变化，也可能有机制变化。
  - 等级权重修正：已持有但未满级时，本道具的再次出现权重会被修正。
  - 解锁条件：部分道具一开始不会解锁，需要满足指定条件。
2. 被动道具升级
  - 首次获得后加入持有列表，显示为“获得道具”。
  - 再次即将获得同一道具时，如果未满级，展示为“道具升级”。
  - 升级会强化已有道具，可以是数值强化，也可以是新增机制。
  - 满级后不再进入普通随机池；若特殊事件强制给到满级道具，则折算为金币或重新抽取。
3. 被动道具触发
  - 构建战斗时：修改本局棋盘、菜谱、目标分、上菜次数等局级参数。
  - 上菜前后：修改候选菜权重、额外生成菜、改变摆放结果。
  - 标签结算前后：追加标签效果、修改某类菜的分值。
  - 最终结算前：追加最终加法、乘法或达标修正。
  - 奖励/商店刷新时：修改奖励池、价格、品质分布或额外选项。
4. UI 展示
  - 原型图最右侧为被动道具列表。
  - 默认展示图标、品质边框、等级角标。
  - hover/click 展示详情：名称、当前等级效果、下一级效果、特殊标记说明。
  - 满级显示 MAX。

## 主动道具
1. 主动道具有多个参数
  - 技能：具体能力是什么，由效果类型和参数描述。
  - 特殊标记：可能在某些事件以及 Boss 奖励中被随机到。
  - 触发时机：在某些阶段可以触发，例如上菜前、上菜后、吃之前、结算后、奖励界面。
  - 获得上限：某些主动道具有单局累计获得上限，到达上限后不再能被随机出。
  - 持有上限：某些主动道具有当前持有上限，到达上限后不再能被随机出，直到消耗掉持有的道具。
  - 消耗规则：默认使用后数量 -1；也可以配置为本局限用一次但不消耗。
2. 主动道具使用
  - 原型图右下角为主动道具列表。
  - 简单主动道具点击后立即生效，例如清空棋盘、额外上菜。
  - 复杂主动道具点击后进入选择模式，例如选择一个菜、一个格子或一本菜谱。
  - 不满足触发时机时置灰，并展示不可用原因。
  - 当前数量为 0 时从列表中隐藏或显示为空槽。
3. 随机主动道具
  - 特殊事件会从带有特殊标记的道具中随机。
  - 随机时都是不放回随机。
  - 若达到获得上限或持有上限，则从候选池中剔除。

## 统一随机规则
1. 所有奖励、事件、商店都使用统一随机池。
2. 筛选顺序：
  - 类型筛选：被动/主动。
  - 解锁筛选：未解锁的道具不进入池。
  - 来源筛选：特殊事件只允许指定特殊标记。
  - 上限筛选：被动满级、主动达到获得上限或持有上限的道具不进入池。
3. 权重计算：
  - 基础权重来自配置。
  - 品质分布由来源决定，例如普通奖励、Boss 奖励、商店、特殊事件。
  - 已持有被动但未满级时，乘以等级权重修正。
4. 同时展示多个道具时，不放回随机。
5. 如果随机范围内没有道具：
  - 先扩大到同来源的全部品质。
  - 再没有时扩大到整个已解锁道具库。
  - 仍然没有时折算为金币，并输出配置警告，方便策划排查。

## 道具表设计
1. 主表：`TbItem` / `GameConfig/Datas/item.xlsx`
  - `id`：唯一 id。
  - `name`：显示名。
  - `desc`：基础描述，可写当前 1 级效果。
  - `kind`：`Passive` 被动 / `Active` 主动。
  - `quality`：品质，`Common` / `Uncommon` / `Rare` / `Epic` / `Legendary`。
  - `specialTags`：特殊标记，多个标记用 `|` 分隔，例如 `BossReward|SpicyBuild`。
  - `maxLevel`：最大等级。被动道具大于 1 时可升级；主动道具一般为 1。
  - `nextLevelWeightMultiplier`：已持有但未满级时，再次进入随机池的权重倍率。
  - `unlockCondition`：解锁条件 id，空串表示默认解锁。
  - `triggerTiming`：主动触发时机，`BeforeServe` / `AfterServe` / `BeforeEat` / `AfterSettlement` / `RewardScreen`；被动填 `None`。
  - `acquireLimit`：单局累计获得上限，`<=0` 表示无限制。
  - `holdLimit`：当前持有上限，`<=0` 表示无限制。
  - `consumeOnUse`：主动道具使用后是否消耗数量。
  - `baseWeight`：随机基础权重。
  - `effectType`：效果类型，由程序注册表分发。
  - `effectValue`：主数值参数。
  - `effectParam`：额外参数，例如标签 id、菜品 id、流派关键词等。
  - `icon`：图标资源路径。
2. 品质概率不写在道具表中，放在奖励来源配置中。
  - 普通奖励、Boss 奖励、商店、特殊事件应分别配置品质分布。
  - 当前阶段可先在程序中给默认分布，后续扩为 `TbItemPool` 或事件/周配置字段。
3. 特殊标记只负责筛选，不直接改变权重。
  - 例如 `SpicyBuild` 表示可以被麻辣流派事件抽到。
  - `BossReward` 表示可以进入 Boss 奖励定向池。
4. 效果参数约定
  - `FinalAddFlat`：`effectValue` 为每级最终加分。
  - `FinalAddMult`：`effectValue` 为 1 级乘区倍率，升级按增量叠加。
  - `TagBonus`：`effectValue` 为加分，`effectParam` 写目标标签 id。
  - `ClearBoard`：不需要额外参数。
  - `ExtraServe`：`effectValue` 表示额外上菜次数，当前先按 1 次处理。

# 分数与奖励
  ## 局内分数
    - 由难度和游戏进度（第几周，第几天）决定一个初始值
    - 可以通过难度标签、boss机制、主动/被动道具等修正分数
  ## 局内奖励
    - 局内奖励有多种，金币、三选一菜品、三选一被动道具、主动道具、三选一棋盘碎片
    - 一般为金币+一个奖励（菜品、道具、碎片）+随机奖励（可能也没有）
    - 金币
      - 一般都有
      - 通用货币、可以进行购物、刷新等等
      - 根据难度、进度等设立一个基准值范围，在范围内随机
    - 菜品、被动道具
      - 配置要求隐藏分
    - 主动道具
      - 纯随机
