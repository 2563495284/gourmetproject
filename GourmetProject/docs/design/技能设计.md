# 技能

## 实现架构：具体子技能库 + 有序引用 + 自动描述

技能配置分两层（表结构见 [`docs/配置表说明.md`](../配置表说明.md) 5.1 节）：

- **具体子技能 `sub_skill`**：一行 = 一条完整效果，含全部 `SkillRuleDef` 字段（trigger/条件/行为/数值/参数）+ `isPassive/signed/descTemplate`。**参数不同即不同子技能**；内容完全相同的子技能可被多个技能复用。
- **技能 `skill`**：`id/termId/subSkills`；`subSkills` 正向、有序引用子技能 id（`|` 分隔），执行顺序即列表下标。描述由所引用子技能的占位符模板**按序自动拼接**。展示标题按 `termId` 术语名（无则空）。

要点：

- **一菜一 skill**：每道菜的 `dish_base.skills` 只引用一个技能 `sk_<菜id>`，该菜的所有效果（计分/被动/甜蜜传递…）都是这个技能的子技能。数据脚本以「多个 skill 片段」的作者友好写法编写，`build_merged_skills()` 在输出阶段按菜合并成单一技能。
- 参数化变体表现为不同子技能行、按内容去重复用。例如「视为N个食物」的 `视为2/4/8个食物` 是同一模板不同 `actionValue` 展平出的不同子技能行；「倍率×5 作用自身」等相同效果则被多个技能复用同一行。当前 47 个菜品技能引用 66 条去重后的具体子技能。
- **甜蜜传递=子技能**：甜蜜传递作为某菜技能的一个子技能，运行时把「本 skill 内的其他子技能」作为外来子技能传给目标，目标在本次美食结算时随自身一并施加（作用域相对目标计算），一次美食生效一次、美食结束清除。传递子技能本身被排除、不会链式传递。详见 [`技能.md`](技能.md) §5.2 与 [`分数结算.md`](分数结算.md)。
- 运行时：适配层 `GameplayContentBuilder` 遍历 `subSkills`，把每个具体子技能合成为现有的 `SkillRuleDef`（`order`=下标）；结算逻辑（`SkillConditionEvaluator`/`SkillRuleEffectSource`/`ServeRuleResolver`）仅在**甜蜜传递**改为规则级外来子技能（`DishInstance.TransferredSkills`、`SkillEffect` 载荷），其余零改动。
- 描述由 `SkillDescComposer` 回填占位符生成（占位符表见配置表说明）。
- 「视为N个食物」不再用 `dish_base.countAs` 承载：**所有 `dish_base.countAs` 恒为 1**，改由被动子技能（Self AddCountAs，补 N-1）表达，作为该菜单一技能的一个子技能（合并前写作 `sk_countasN` 片段）。描述用 `{countas}=actionValue+1` 显示总数 N；运行时 `base 1 + (N-1) = N` 有效视为食物数不变。`ss_count_as`（定向/条件「额外视为」）与 `ss_count_as_filled` 仍为增量语义。
