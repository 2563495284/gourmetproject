# 技能

## 实现架构：具体子技能库 + 有序引用 + 自动描述

技能配置分两层（表结构见 [`docs/配置表说明.md`](../配置表说明.md) 5.1 节）：

- **具体子技能 `sub_skill`**：一行 = 某个技能的一条独占完整效果，含全部 `SkillRuleDef` 字段（trigger/条件/行为/数值/参数）+ `signed/descTemplate`。ID 为 `<skillId>_<从 1 开始的序号>`；不跨技能复用，内容相同也分别写行。
- **技能 `skill`**：`id/termId/subSkills`；`subSkills` 正向、有序引用子技能 id（`|` 分隔），执行顺序即列表下标。描述由所引用子技能的占位符模板**按序自动拼接**。展示标题按 `termId` 术语名（无则空）。

要点：

- **一个食物一个 skill**：每个食物的 `dish_base.skills` 只引用一个技能 `sk_<食物id>`，该食物的所有效果（计分/被动/甜蜜传递…）都是这个技能的子技能。数据脚本以「多个 skill 片段」的作者友好写法编写，`build_merged_skills()` 在输出阶段按菜合并成单一技能。
- 每个技能按 `subSkills` 顺序维护自己的子技能行。例如 `sk_cookie` 的第一条效果是 `sk_cookie_1`，`sk_macaron` 的两条效果依次是 `sk_macaron_1`、`sk_macaron_2`。相同效果出现在不同技能时也分别配置，当前正式表共有 60 个技能、80 条独占子技能。
- **甜蜜传递=子技能**：甜蜜传递作为某菜技能的一个子技能，运行时把「本 skill 内的其他子技能」作为外来子技能传给目标。目标正常结算时会施加已持有的外来子技能（作用域相对目标计算）；每次成功接收新传递时，还会立即重结算当时累计获得的全部 `OnSettle` 外来子技能，同轮不去重，食物结束清除。传递子技能本身被排除、不会链式传递。详见 [`技能.md`](技能.md) §5.2 与 [`美味值结算.md`](美味值结算.md)。
- 运行时：适配层 `GameplayContentBuilder` 遍历 `subSkills`，把每个具体子技能合成为现有的 `SkillRuleDef`（`order`=下标）；结算逻辑（`SkillConditionEvaluator`/`SkillRuleEffectSource`/`ServeRuleResolver`）仅在**甜蜜传递**改为规则级外来子技能（`DishInstance.TransferredSkills`、`SkillEffect` 载荷），其余零改动。
- 描述由 `SkillDescComposer` 回填占位符生成（占位符表见配置表说明）。
- 「视为 N 份食物」是食物本身的静态属性，直接写入 `dish_base.countAs`，不再生成只负责展示份数的被动子技能。定向/条件「额外视为 N 份食物」仍使用主动 `AddCountAs`，在当前有效份数上累加，并只在本次结算内生效。
